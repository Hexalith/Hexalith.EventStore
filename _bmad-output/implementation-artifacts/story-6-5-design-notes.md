## Design Notes

The new gateway accepts v1 wire only by exact domain-scoped registered alias during reader-first rollout; it persists that event as v1. Stop v1 admission only after all old writers and in-flight v1 requests are drained with evidence. Every projection, subscription, replay, stream, and Admin DTO carries stored metadata/type/version separately from effective canonical type/version; normalized payloads carry an explicit already-adapted marker, so receivers never infer provenance from a CLR name or upcast twice. Publish the original persisted event's readable payload bytes and stored version/type for both initial delivery and retry; adapt only in consumers.

Each legacy alias declares its source version and a schema-specific aggregate-id extractor or explicit no-payload-identity policy; envelope/key identity remains mandatory. A version-specific extractor verifies any payload identity after every hop. Fingerprints are SHA-256 of canonical sorted UTF-8 descriptors, alias/version/identity policies, edge metadata, serializer identity, and each upcaster implementation assembly's content digest. Permanent malformed or identity-poison subscription deliveries require a durable AD-31 quarantine before acknowledgement; transient/cancel/deployment failures retry. Marker records bind MessageId to addressed scope and a stable original-event digest; same ID with different evidence is conflict, never duplicate. Legacy full-array handlers may use their existing one-array boundary, filled from validated bounded pages without an extra full-stream upcast buffer; scratch state is not authoritative until complete. Inventory `StreamsController` and `AdminStreamQueryController` as readers.

Give downstream DTOs distinct, exact stored and effective member names (for example `StoredEventContractType`/`StoredPayloadVersion` and `EffectiveEventContractType`/`EffectivePayloadVersion`) and specify JSON names, constructor defaults, and mappings to old fields. On v2 stored read, `EventTypeName` must exactly equal `EventContractType`; on v1 write, preappend payload identity follows its registered alias policy, including `NoPayloadIdentity`, while mandatory envelope/key identity still applies. After every hop, check UTF-8, single JSON object, depth and byte bound before the next hop. Inventory `DomainSharedProjectionRebuildDispatcher` and its history/inventory fingerprint paths as consumers; shared rebuild must validate and adapt each event before fingerprint or handler use.

Separate a canonical digest of immutable stored evidence from a delivery digest computed over the original readable payload and stable publication metadata. Fully specify domain-separated byte encoding, every ordered field, null versus absent, integer and UTC timestamp forms, sorted extension encoding, and raw byte lengths. The trusted gateway attests the stored digest from storage; a subscriber validates authenticated origin and recomputes the delivery digest from bytes it receives. The marker binds both digests and scope and rejects changed or missing attestation. Never claim a subscriber can recompute protected stored bytes. Require registration/readiness proof of handler idempotency-key use or a transactional effect/receipt boundary before side-effect dispatch; a crash before durable `Dispatched` must safely redeliver.

Preserve historical readability under configurable writer sizes: inventory the largest reachable legacy event per provider before rollout; use a bounded legacy-read ceiling configured at or above that measured maximum (with a fixed maximum upper safety bound) and block cutover with a typed result if the corpus exceeds it. Retain a separate 1 MiB limit for new writes and upcast outputs if desired. A reused legacy alias with indistinguishable historical schemas is not guessed: corpus preflight fails the readiness gate and requires explicitly approved offline evidence migration. Folded snapshots need an aggregate-state schema/Apply compatibility witness tied to the registry; if absent or changed, retain the snapshot, bypass it, and full-replay before any command. Preserve `AggregateActor`'s ambiguous-save durable readback on cancellation or storage exception; decide committed versus uncommitted from the witness before cleanup, response or retry.

Put all immutable approval rules, including the exact hash boundary and authorization sentence, above the receipt marker. Exclude only the mutable receipt fields from the digest, and ensure the document's claim about digest coverage matches the bytes actually hashed. After rederivation, recompute the digest without self-approval.

Add `MetadataVersion`, `EventContractType`, and `PayloadVersion` to the intermediate `ISerializedEventPayload` carrier and both serialized/rejection wrappers; map them explicitly in `DaprDomainServiceInvoker.ToDomainResult`, `EventPersister`, and publication/replay adapters. Keep the existing members/constructors valid. Add all stable stored metadata needed by the delivery digest, including `AggregateType`, `DomainServiceVersion`, and both stored/readable serialization-format provenance, to the subscription DTO. Specify precisely which format the delivery digest hashes and make the published field match it. The stored digest uses original stored format; the delivery digest uses pinned readable format, with distinct field lists and versioned domain separators. A subscriber recomputes from fields it actually receives.

Canonical stored evidence must survive typed normalization: either retain a raw storage-envelope decoder/presence bitmap for absent/null and null/empty extensions before `Contracts.Events.EventEnvelope` canonicalizes them, or define one canonical typed representation and hash it consistently. Do not claim a digest over raw distinctions after those distinctions are erased. Reject duplicate JSON object property names recursively before identity extraction, after each upcast, and before current-type deserialization. Compare `AggregateType` against registered command/aggregate route metadata or persisted aggregate metadata, not `AggregateIdentity` alone. Remove the unimplemented discriminator exception for reused aliases; all alias reuse without an already persisted unambiguous discriminator blocks rollout and requires separately approved offline evidence migration.

Preserve the approved folded-snapshot v1 envelope: store the new state-schema/Apply witness in one additive actor-owned side record at `AggregateIdentity.SnapshotKey + ":evolution-witness"`, without rewriting old snapshot bytes. Stage the snapshot and witness together in one actor state batch, save once, then read both back before claiming authority; on absent, stale, partial or ambiguous evidence bypass and full-replay. Existing witness-less snapshots safely bypass once, full-replay, and atomically refold/write a witnessed snapshot at the same durable actor boundary; if refold cannot commit, keep old snapshot and retry without claiming bounded tail cost. Migration/readiness must budget that one-time replay and not claim 6.2 tail performance until refold completes. Preflight active writer payload size and event-count distributions as well as historical maximums; hold v2 switch or migrate producers that exceed new limits.

Legacy publication and marker migration are explicit rollout gates. Drain or reconcile old outbox/in-flight publications before enabling stable pinning; a retry lacking a pin may publish only if durable prior-delivery bytes can be proven equal, otherwise hold with operator evidence and never emit altered bytes under the same MessageId. Queued v1 deliveries without attestation use an authenticated trusted-gateway lookup by scoped MessageId to fetch original storage evidence, compute both digests, and issue an attested stored-form delivery before handler admission; lookup failure retries, never quarantines valid legacy traffic. Upgrade old marker records under CAS only after matching scoped actor evidence and effect receipt: completed records remain completed, dispatched records finalize without re-execution, and in-progress records retry only through enforced idempotency; ambiguous/missing proof blocks for operator reconciliation and never silently redispatches. Inventory and route `AdminTraceQueryController.GetEventsAsync` through shared validation with stored/effective safe evidence.

Use a bounded output writer supplied by the pipeline to every upcaster so its 1 MiB per-hop output ceiling and 128 MiB total scratch ceiling are enforced during allocation, not only after return. Treat explicit deterministic schema/input rejection as permanent poison, cancellation as cancellation, and all other hop exceptions as retryable deployment/infrastructure failure; the same classifier applies to every consumer. Specify a typed exception/result for the deterministic branch and include vectors for oversized emission, duplicate JSON members, legacy queue/marker migration, old snapshots, active producer limits, and Admin trace.

Describe the whole receipt section after the standalone marker as mutable and excluded, but freeze an exact receipt schema and validator above the marker: fixed field names, one row each, strict digest/name/UTC date/authorization sentence, no extra approval-bearing rows, and fail on altered labels or missing values. Admit v1 wire events when both new pair members are absent **or both explicitly JSON null**, with metadata version absent/null/1; mixed presence or non-null partial pair is malformed. Keep raw JSON presence long enough to distinguish those shapes. Add a registered/capability-gated v2 overload or service for `DomainServiceWireResult.FromDomainResult` that receives an immutable descriptor registry and cutover mode; old static helper stays v1. Specify domain endpoint selection, descriptor lookup, alias/canonical output, and bounded serialization before allocating a full byte array. The writer must never emit a v2 pair without metadata version 2 and must not silently choose mode.

Reject duplicate JSON names under both ordinal identity and the pinned deserializer's case-insensitive comparer at every object level, including each upcast output. Register a target-version schema validator for every version, fingerprint its implementation and options, and invoke it after each hop before the next. Treat explicit deterministic rejection as poison; an unknown/missing validator fails readiness. Projection/replay DTOs retain their existing narrow security shape, but the authenticated gateway must bind their stored provenance to addressed scope, sequence, message ID, stored digest, registry fingerprint and target version in an internal attestation/route envelope. The receiving domain service verifies it or fetches original evidence from the trusted gateway before accepting `isAdapted`; no untrusted DTO may assert stored validation. Include the coordinated command actor source read and `ProjectionEventWireBuilder` path in the inventory; bound/paginate its policy input or gate legacy full-array policies by numeric count/byte ceilings and fail typed without partial policy results.

Extend the fingerprint codec to cover the exact implementation assembly bytes and configuration IDs of envelope validation, shared chain executor, attestation verifier and schema validators, plus each upcaster's `SerializerId` in E records. Do not claim two readers have equivalent behavior unless all these records match. Define snapshot side-record digest over the approved 6.1 canonical folded-state bytes and selected exact envelope fields, with a fixed field order and encoding; compute before actor write and verify after readback, independent of provider JSON representation. Keep approved v1 snapshot bytes unmodified.

For old markers, grandfather a durable legacy `Completed`/`Dispatched` state under CAS only with independent scoped actor evidence plus route-specific receipt/outbox/catalog proof; never invent a new effect receipt: Completed remains terminal, Dispatched finalizes only; conflict or missing actor evidence blocks. Old InProgress may retry only after the handler is migrated to a proven durable idempotency contract, otherwise operator reconciliation. Freeze an additive handler effect interface/receipt type and exact key `(scope, MessageId, delivery digest, handler route)`, router precedence and transaction/idempotency semantics; existing handlers remain callable through named adapters but cannot claim production safe retry until migrated. Freeze an exact additive token-aware processor interface, its method signature, and router precedence over the old interface. A route with both implementations must select one deterministically; propagate token through it.

Bound extension metadata (numeric entry count, per-key/value UTF-8 bytes and total bytes) before hashing or publishing, and preflight historical provider metadata against those limits; preserve original bytes and block rollout if exceeded. Pin the exact CloudEvent body bytes **and** id/type/source/content-type/extension headers; send via a verified raw-byte DAPR publisher abstraction rather than generic object serialization, fail readiness if exact-byte send is unsupported, and compare sent bytes on retry. Keep old attestation verification keys until every pin, queue, quarantine replay and rollback target signed with them has drained or expired with durable evidence. No key removal based only on wall-clock overlap.

Bind `EventRouteAttestation` to effective payload SHA-256, effective serialization format, target type/version, source digest, addressed scope, sequence, MessageId and registry fingerprint; receiver recomputes the effective digest before skipping the chain. A missing/changed attestation forces authenticated gateway lookup and revalidation from stored evidence, never trusted Apply. On actor commit with no pin, a recovery worker deterministically derives a first pin from durable stored event/readability and stable serializer configuration **before any send**; commit/outbox witness proves whether an old sender may already have sent it. If prior send is ambiguous, hold for operator reconciliation; never send an unpinned changed body.

Separate marker duplicate identity from deployment fingerprint: bind immutable source/delivery digests, scope, sequence and route; retain fingerprint as audit/readiness metadata but a compatible reader upgrade alone cannot turn a duplicate into conflict. Use one global durable MessageId reservation/index, keyed by MessageId across all tenants/scopes and routes and checked before route-specific marker acquisition; permit intentional multi-handler delivery only when same event evidence and cataloged routes are proven. Legacy marker migration needs independent binding evidence (old route/receipt/outbox index or unique historical MessageId inventory), not a single convenient actor lookup; ambiguous IDs block for operator resolution, never grandfather incorrectly.

Authenticate or compare pinned CloudEvent `id`, `type`, `source`, content type, topic and all routing-relevant headers at subscriber admission against signed/pinned evidence; a changed header or destination cannot silently redirect a valid body. A valid addressed event with no registered handler is a typed deployment/readiness failure that retries without acknowledgement; only a predeclared authenticated route filter can end it; AD-31 capture alone never acknowledges a valid addressed event without a handler. Specify provider-level bounded raw actor state reads (streaming/size-limited byte API or enforced DAPR transport max before typed materialization); if unavailable, fail readiness for the 128 MiB raw-envelope cap and retain corpus preflight as additional evidence. Preappend v1 identity uses its exact registered alias/schema extractor or `NoPayloadIdentity`, not `IEventContract`; v2 current CLR payloads require `IEventContract` checks.

When 6.2 folded snapshot runtime is absent, 6.6 uses full replay and does not require or write the side witness; 6.2 owns introducing folded snapshots, and 6.6 integrates the witness when that runtime exists, without editing approved v1 snapshot bytes. Scope fingerprint negotiation per affected domain; compare all serving readers/publishers for that domain and preserve domain-specific aliases through rollback. V1 writer may emit `PrimaryWriteAlias` only if its `SourceVersion` schema exactly matches serialized bytes; otherwise a registered downserializer must produce and validate that source schema, or the writer fails readiness. Freeze a token-aware replay interface/adapter and route selection independent of legacy `IDomainProcessor`; a synchronous legacy replay checks token before and after and cannot claim mid-call interruption. Inventory and route `DaprAggregateStateReconstructor` DTO conversion and `TrustedEffectRetentionGate` retained-source read through the shared validation path before replay or effect authorization.

Loop-6 fingerprint correction: The D record binds the **exact current CLR payload type** (assembly-qualified type identity used internally, never exposed publicly) and its assembly-file digest, aggregate Apply implementation and state serializer. Each A record binds its **own** alias-specific validator ID, options ID and implementation assembly-file digest as well as source version/identity policy; V records bind version-wide validators separately. An alias-specific validator can differ from another alias at the same version without changing V, so A must carry it. Keep the canonical byte codec, sorted records, domain scoping, edge serializer IDs, shared validator/executor/signer/publisher/marker implementation digests, and exact source-compatible 64-character kebab grammar. `EventUpcastResult` returns declared domain/type/version/format metadata alongside bounded-writer bytes, and every hop compares it to the registered edge before invoking the next.

Loop-6 writer negotiation: The gateway's per-domain deployment capability record owns `EventWriterMode` and the approved `RegistryFingerprint`. Add optional `WriterMode` and `RegistryFingerprint` properties to `DomainServiceRequest` and `DomainServiceWireResult`, with unchanged existing constructors; missing request mode means v1. The gateway sets both on each request from that capability record, and the domain router validates them against its registered endpoint descriptor. The router invokes **one** capability-selected bounded writer service for both successful processor results and admission-stage rejection results, then echoes the mode/fingerprint in the wire result. Gateway validates echoed mode/fingerprint and every event's matching version triplet before append; absent/mismatched echo in v2 mode fails closed, never falls back. The old static `FromDomainResult` remains an explicitly v1 helper. No response itself may advertise or select a mode different from the request. Verify this path through `DomainServiceRequestRouter.ProcessAsync`, DAPR invocation, wire mapping, and `EventPersister`.

Loop-6 legacy size rule: The active v1 writer configuration and gateway append admission must be fenced to the deployed reader's provider-specific legacy readable ceiling (at most 64 MiB payload and at most 128 MiB raw envelope), **before** the new reader fleet serves that domain. Corpus and in-flight v1 requests must pass the same bound; overlimit writers are held or migrated, with no new unreadable append. The 1 MiB cap applies to v2 writes and to **each upcast output**, not to a legacy current-version source with zero hops. A validated v1 event already at the registered current version can remain readable up to the measured legacy ceiling and enter allow-listed deserialization, subject to consumer page/array budgets. Corpus preflight must prove for every reachable alias/version/size either this no-hop current-schema path or a registered chain whose every output meets 1 MiB; otherwise reader readiness fails. Do not truncate a valid historical event to make it fit. Before any serializer, protection call, allocator or staged state write, reject a negative stream head or `currentSequence > long.MaxValue - eventCount` with typed `SequenceExhausted`; use checked arithmetic for each sequence and new head. Global position allocation has its own checked bound.

Loop-6 readers and durable progress: Explicitly include `ProjectionDeliveryRetryWorker.LoadHistoryAsync` and its `ProjectionEventWireBuilder` call, `EventStoreProjectionDeliveryHistoryReader.ReadAsync`, and `ProjectionUpdateOrchestrator`'s full-history read in the shared gateway plan. Each validates/adapts the complete required prefix before invoking handlers or computing a fingerprint; no retry bypass. Replace Admin/trace `GetEventsAsync(0)` full materialization with validated pages of at most 256 events and 64 MiB readable bytes. An existing Admin endpoint that must return an array gets one completed bounded array of at most 100,000 events and 64 MiB; above either bound return typed `LegacyArrayLimit` before responding, never partial results. For live/rebuild projection deterministic bad history, durably capture AD-31 evidence where available, **stop at the offending sequence**, leave checkpoint at last contiguous completed sequence and state non-current, and retry from that checkpoint after a validated repair/migration. Quarantine is evidence storage, never permission to skip or advance past the event. Missing AD-31 sink does not turn the failure into a successful projection.

Loop-6 attestation protocol: Use ECDSA P-256 with SHA-256 and fixed 64-byte IEEE P1363 signature encoding. Key IDs are ASCII lowercase kebab-case, 1–64 bytes, and resolve through a configured per-domain/per-purpose trust map to exact SubjectPublicKeyInfo bytes; unknown, revoked or wrong-purpose keys fail before any handler. Sign the exact canonical bytes `HX-EV-SIG-1\0`, codec byte `01`, purpose byte (`01` route, `02` delivery), then tagged-length key ID and tagged-length claim bytes using the §7 scalar codec. Route claim fields in order are `StoredDigest` (raw 32 bytes), addressed tenant/domain/aggregate ID/type, sequence, MessageId, target canonical type/version, active `RegistryFingerprint`, effective payload SHA-256 (raw 32 bytes), and exact effective serialization format. Delivery claim fields in order are `StoredDigest`, `DeliveryDigest` (both raw 32 bytes), addressed tenant/domain/aggregate ID/type, sequence, MessageId, and active `RegistryFingerprint`; the delivery digest already binds topic/component/CloudEvent fields/headers. Sign and pin the signature bytes once, then retry the same bytes. At receiver, authenticate signature and purpose, compare all DTO scope/target/stored/effective provenance members to signed claims and recomputed source/delivery/effective digests, and require the active domain fingerprint before Apply or handler routing. In stored-form delivery, derived provenance must equal the signed stored fields; untrusted extra fields cannot override them. Missing or stale route attestation triggers authenticated source lookup and full revalidation, never direct Apply.

Loop-6 identity/compatibility: Use a **global** CAS reservation, keyed as `event-id-reservation:` plus lowercase SHA-256 of the exact UTF-8 MessageId, with the exact MessageId retained in the record and compared to detect key collision. It spans all tenants, domains and routes; conflict details are not leaked across tenants. A tenant-specific marker still carries its own route and digests after reservation. Do not NFC-normalize or reject otherwise valid non-NFC metadata strings on historical read: `UserId`, `DomainServiceVersion` and other existing v1 strings were persisted as supplied. The canonical digest hashes each decoded string's exact UTF-8 scalar sequence, with no Unicode normalization for either version; JSON escape spelling and provider field order remain irrelevant. Static event/domain identifiers remain ASCII under the existing grammar. Validate invalid Unicode and duplicate JSON names without rewriting history. Update the two stale `epics.md` Current reconciliation paragraphs to say 6.5 is in progress with an unapproved draft and 6.6 is blocked by missing human content approval, while preserving its original acceptance criteria.

Loop-7 additive DTO and ingress correction: `ReplayEventEnvelope.MetadataVersion` is already a required `int` constructor member and MUST be retained unchanged, not added as nullable. `EventStoreDomainEventEnvelope.GlobalPosition`, `CausationId`, and `UserId` already exist and MUST be reused, not redeclared. Add only missing stored/effective provenance and the optional `ReadableExtensions`/`readableExtensions` map needed for `DeliveryDigest`; old positional constructors remain callable. Define an inbound `VerifiedDeliveryContext` that contains exact received CloudEvent core attributes, pubsub component, topic, raw body bytes and application routing headers. `MapEventStoreDomainEvents` must replace its DTO-only handler with a bounded raw CloudEvent/HTTP ingress adapter that authenticates those transport fields and produces `(EventStoreDomainEventEnvelope, VerifiedDeliveryContext)` for the processor; a deserialized DTO or caller-supplied headers alone never count as transport authority. Legacy queued V1 fallback still performs authenticated gateway lookup before handler admission.

Loop-7 routing metadata codec: Pin and hash CloudEvent `specversion=1.0`, `id`, `type`, `source`, optional `subject`, optional `time` as exact UTC ticks, and `datacontenttype`, plus pubsub component/topic. The only application-controlled routing extension/header names are `hx-tenant-id`, `hx-domain`, `hx-aggregate-id`, `hx-aggregate-type`, `hx-event-contract-type`, and `hx-payload-version`; every one is present on new deliveries and matches signed stored-form evidence. Canonicalize names to lowercase ASCII, reject duplicate names even with case variants, sort by ordinal UTF-8 name and encode exact UTF-8 values with the existing bounded map codec. Unknown `hx-*` names fail admission; broker-added non-`hx-*` transport headers are ignored for digest and MUST NOT influence routing, identity, handler selection or approval. The publisher pins this exact map and the inbound adapter extracts it from trusted transport metadata; an unavailable field fails transport readiness rather than being guessed from the body.

Loop-7 registry and signing readiness: Every reachable payload version, including older canonical V2 versions, has a version-specific serializer ID, options ID and exact format in its V descriptor/fingerprint record; the alias record independently binds source serializer and validator. Fingerprint S also contains `TrustMapDigest`: SHA-256 over canonically sorted per-domain/per-purpose records of key ID, exact SubjectPublicKeyInfo SHA-256 and revocation/validity state, plus the signer algorithm ID/options. Two services with different trusted key bytes or purposes cannot claim equal current capability. Rotation is verifier-first: all affected subscribers/readers advertise readiness for the new key and approved registry before a publisher signs with it; old verification keys and approved prior fingerprints remain for pinned obligations. Unknown-key or not-yet-ready capability is retry/hold without poison acknowledgement. Revoke only with a durable conflict/incident decision, and do not discard keys while old signed work can arrive.

Loop-7 V1 and memory bounds: Production `DomainServiceRequestRouter` uses the same bounded writer service for V1 and V2; the old static V1 helper remains callable for compatibility but is not the production path after reader rollout. V1 command results have a fixed maximum of 1,000 events and per-event readable ceiling at most 64 MiB; active producers/configurations above either limit are measured and held/migrated before the bounded reader fleet serves. Count is checked before serialization or full wire-result allocation, and each event uses a bounded writer. The 64 MiB page/array payload count is a separate content limit; also cap one required materialized array to 256 MiB of checked conservative accounting (`stored bytes + readable bytes + encoded metadata/extensions + 8192 bytes per event`) and active scratch apart from that array to 128 MiB. The array budget is charged before allocating each event and stops with `LegacyArrayLimit` before handler/response if exceeded. Implementations may use a stricter measured layout bound, never a looser one. These caps, preflight and the no-extra-full-array rule must agree for a 64 MiB legacy current-source test and for 100,000 small events with maximum metadata.

Loop-7 global ID and handler route: Generate event MessageIds and compute each proposed stored digest before actor save. Reserve every ID in deterministic order in one authoritative `IEventMessageReservationStore`, backed by a configured shared strongly consistent state component with atomic per-key ETag/CAS across all gateway, publisher and subscriber instances; no local/per-tenant substitute. Reservation state is `Pending(operation ID, scope, sequence, digest)` then `Committed`; actor append and the reservation are a reconciled two-phase protocol, not falsely claimed atomic across stores. A pending conflict blocks another append. After actor save, durable actor event/metadata/outbox readback proves commit before finalizing reservations; failed save releases pending IDs only after durable proof of no commit; unknown result holds for reconciliation. Subscriber checks the same committed reservation, and old corpus is preflighted/backfilled before the gate opens. A cataloged handler route has an explicit stable `HandlerRouteId` (existing 64-character kebab grammar), unique within domain/contract type, never derived from CLR class/registration order. Consumer route-catalog fingerprint binds ID-to-handler mapping; rename requires an explicit alias/migration that retains old marker/effect key interpretation and proves no duplicate effect. Same event may have multiple cataloged routes under one global reservation.

Loop-7 complete-prefix and special paths: Authenticate a `PrefixAttestation` for every cross-process replay/projection request: addressed scope, start/end inclusive sequence, admitted stream head/target, event count, ordered digest-list SHA-256, current registry fingerprint and optional verified snapshot sequence/witness anchor. It uses the route-signature algorithm/codec with a distinct purpose byte. Receiver checks exact count, start/end/head, contiguous sequence, each event digest/order and `UpToSequence` completion before Apply; a page is never mistaken for full history. If a snapshot anchor is absent, required replay starts at sequence 1; a missing prefix fails typed. Register an explicit per-domain framework descriptor/adapter for `AggregateTerminated` (`IRejectionEvent` without `IEventContract`) with canonical type, aggregate-ID extractor and schema validator, and fingerprint it; V2 rejection serialization uses that allow-listed exception, while other non-contract rejection types block cutover until registered/migrated. Old authenticated `DomainServiceRequest` with **both** mode and fingerprint absent is V1 and uses exact aliases; a mixed absent/present pair fails, and explicit V2 requires both. A new signing key cannot be used before verifier-first readiness. `CoordinatedCommandActor`'s target-side non-fenced retry must use an actor-owned causation/idempotency witness or validated bounded pages with the legacy count/byte limits; its current `GetEventsAsync(0).Any` is not an allowed bypass. Exceeding the fallback scan cap holds/retries without asserting the target event is absent.

Loop-8 approval and exact bytes: A receipt row alone is not proof of human authorship. Add `ApprovalEvidence` as a sixth receipt field: an immutable URL/ID of an authenticated GitHub review or issue comment by the named human containing the exact digest and exact authorization sentence. The gate validator must fetch or independently inspect that source, confirm the actor/name, UTC timestamp, digest and sentence, and reject a missing, deleted, conditional or mismatched event; a local file or assistant-entered row cannot substitute. The receipt remains outside the normative hash, while this evidence rule and exact row schema stay inside it. Clarify that `in-progress` tracker state is allowed before approval; only Story 6.5 `done` and Story 6.6 authorization require a valid receipt.

Loop-8 codec closure: Freeze a complete binary manifest table, not prose “fields above.” For each D/V/A/E/S record specify its exact one-byte record tag, primary key components, count, each one-byte field tag in fixed order, scalar type and nullable encoding; nested version records are separate V rows sorted by `(kind, domain, canonical type, version, alias/edge key)` in unsigned UTF-8 byte order. Reuse the §7 presence/length codec for optional values, reject unknown/duplicate fields, and include exact identity-extractor implementation assembly-file SHA-256 and options in V and A. For signed route, delivery and prefix claims, list every field with exact tag/type/order and null rule and state the signature input's exact purpose/key-ID/claim-length encoding. The ordered prefix digest list is SHA-256 of `HX-EV-PREFIX-LIST-1\0`, codec `01`, unsigned 32-bit big-endian count, then each contiguous entry as signed 64-bit big-endian sequence followed by exactly 32 raw stored-digest bytes; no delimiters or JSON. PrefixAttestation signs that list hash, count, start/end/head and scope, and verifies them all.

Loop-8 incremental and protected-read proof: An incremental projection starting at checkpoint+1 needs an authenticated durable checkpoint anchor: scope, projection route, last completed sequence, cumulative prior-prefix digest, state/checkpoint readback witness and source head, signed with distinct purpose and active fingerprint. The dispatcher verifies the checkpoint persisted and the requested tail begins exactly there; without the anchor it full-rebuilds from sequence 1, never treats a page as complete. Existing `IEventPayloadProtectionService` returns a whole byte array and cannot by itself guarantee a readable-size cap before allocation. Add a bounded/streamed unprotect API that receives the max readable bytes and fails before exceeding it, or require a provider-enforced output bound with persisted proof; providers lacking that primitive fail bounded-read readiness. Keep the original protected bytes and reason on failure. Upcaster hard limits are on pipeline-owned buffers and bounded-writer output; arbitrary trusted implementation-local allocations are **not** falsely claimed to be per-call bounded. Every registered upcaster must use the supplied bounded scratch allocator for large work, pass review/measurement and run under a process memory budget; unexpected OOM is retryable dependency failure, never poison. Set pipeline-managed chain scratch to 128 MiB so a 64 MiB source plus validation and a 1 MiB hop can fit; raw-envelope and one required result-array budgets are separate.

Loop-8 total-output and snapshot proof: In addition to V1 at most 1,000 events and per-event at most 64 MiB, cap the **entire serialized V1 command result** at 128 MiB, including wire JSON/base64 and metadata, with a streaming/bounded writer before materialization. A result over that cap is held/migrated before new reader rollout; one 64 MiB payload can fit after base64 overhead if metadata fits. `IncludeTimeline` may return at most 1,000 entries and 64 MiB cumulative canonical serialized state bytes; charge each state before appending, fail `TimelineLimit` without partial response. Snapshot witness `SnapshotDigest` must include the complete canonical `EventStorePayloadProtectionMetadata`: state, metadata version, scheme, key alias, content hint and sorted compatibility flags, with explicit null encoding, in addition to approved folded-state and snapshot envelope fields. Do not expose key alias in diagnostics.

Loop-8 rollout and dispositions: Since `TrustMapDigest` is in the active registry fingerprint, adding a verifier key first creates a transition mismatch. Fence affected-domain V2 writes and new signing while trust is distributed; all receivers/publishers install dual old/new trust, attest one matching new fingerprint, then resume writes and optionally activate the new signing key. Old queued signatures verify under the approved prior-fingerprint ledger until drained. Define `PredeclaredRouteFilter` as a consumer catalog record with stable filter ID, exact domain/topic/type/tenant-scope predicate, implementation/config digest and `HandlerCatalogFingerprint` binding. It may acknowledge only an **authenticated out-of-scope** event that fails its frozen predicate; it cannot classify an addressed valid event with no handler as filtered. On subscription overlimit, a complete authenticated immutable source whose bytes violate an agreed permanent schema/metadata limit is poison: durable AD-31 capture before ack. Unknown/untrusted transport, active-capability mismatch or provider limits are hold/retry and never ack. Every peer uses this same classifier; no “hold or quarantine” discretionary branch.


Loop-9 command and progress closure: Normal `AggregateActor` command rehydration and `DomainProcessorStateRehydrator` must consume the same authenticated source and complete-prefix/snapshot proof before any Apply.
