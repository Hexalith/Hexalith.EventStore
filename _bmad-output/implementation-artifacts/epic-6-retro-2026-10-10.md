### Diff-scope review: adversarial, edge cases, verification gaps

The `bmad-review` lenses examined the staged, 1,821-line code diff over 15 principal files. Findings below were checked against current source and tests. The full 443-commit diff was too interleaved with other epics for code-lens attribution; this is a narrowed review. Adversarial reports concerning direct publication or rehydration of malformed envelopes were dropped because the reviewed evidence did not establish an unvalidated production route to those methods (`EventPersister.cs:129-133`; `EventStreamReader.cs:149,169`; `AggregateActor.cs:1882,4626`).

**REV-1 — reconciliation and named rebuild lack upcast regression assertions.** The implementation upcasts before `ReconcileAsync` and `PrepareRebuildAsync` (`src/Hexalith.EventStore.DomainService/DomainProjectionDispatcher.cs:156-171,474-495`), but their tests accept any `ProjectionRequest` and assert only status or batch keys (`tests/Hexalith.EventStore.DomainService.Tests/DomainProjectionDispatcherV2Tests.cs:328-353,402-449`). The versioned projection test covers ordinary dispatch (`tests/Hexalith.EventStore.DomainService.Tests/VersionedProjectionDispatchTests.cs:135-167`). Removing either upcast call could let a renamed V1 event reach a handler in its old shape without those tests failing. **Disposition:** fix now with captured-handler assertions for a registered rename and transformed JSON in both paths. **Upstream lesson:** each distinct projection entry point needs its own versioned event assertion.

**REV-2 — a pre-registered processor can bypass host registry injection.** `AddEventStoreClient<TProcessor>` uses `TryAddScoped` for the only factory that sets `IEventPayloadEvolutionAware.EvolutionRegistry` (`src/Hexalith.EventStore.Client/Registration/EventStoreServiceCollectionExtensions.cs:129-139`). If a host registered `TProcessor` first, the factory is skipped and the resolved aggregate retains a null registry (`src/Hexalith.EventStore.Client/Aggregates/EventStoreAggregate.cs:29-32`); the existing registration tests cover only registration by EventStore itself (`tests/Hexalith.EventStore.Client.Tests/Registration/AddEventStoreTests.cs:169-234`). A separately registered upcaster can then be missed on replay. **Disposition:** fix now if pre-registration is supported; otherwise document and enforce the registration contract. **Upstream lesson:** DI ordering is a behavioral boundary and needs a targeted test.

**VER-1 — the broad secrets gate is still red.** The focused current-tree invocation of `SecretsProtectionTests.TrackedReusableContent_DoesNotContainUsableSecrets` failed with 791 reported path/line matches (see Behavior verification; test assertion at `tests/Hexalith.EventStore.Server.Tests/Security/SecretsProtectionTests.cs:32-44`). The earlier Story 6.6 owner exception cited 19 findings and the later execution record cited 152 (`spec-6-6-event-versioning-and-upcasting-implementation-3.md:386,419-424`); neither is proof that the current 791 findings are safe. The present matches include reusable agent-skill resources, so attribution to 6.6 is unproven. **Disposition:** fix now through separate security/CI triage. **Upstream lesson:** a scoped story exception must not silently become a general CI pass.
