## Intent

**Problem:** Infrastructure and persistence-conflict rejection paths clear staged actor state on their successful paths, but remediation failures and the unconditional pending-count finalizer can still expose a later save to residual event, metadata, snapshot, publication, pipeline, or pending mutations. Existing tests prove calls and retryability rather than the committed end state.

**Approach:** Harden the `AggregateActor` failure boundary so every retry or rejection clears failed-attempt state before restaging or saving, preserves the earliest causal failure when remediation also fails, and never claims safe discard without durable evidence. Add deterministic fault-injection tests that stage concrete values and inspect committed state after each terminal path.

## Boundaries & Constraints

**Always:** Keep `AggregateActor` as the sole durable event-mutation coordinator; use clear-before-restage/save ordering; preserve support-safe redaction; retain retryable infrastructure/conflict semantics; apply `ConfigureAwait(false)` to every production await; verify exact committed keys and values after failures.

**Never:** Change retry counts, event identity, append fencing, idempotency rules, publication recovery, projection triggering, public contracts, packages, UI, topology, or dead-letter retry policy. Do not treat call counts, HTTP results, or advisory status as durable-state proof, and do not modify `references/` content or unrelated worktree changes.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|----------------------------|----------------|
| Infrastructure rejection | Concrete event, metadata, snapshot, or publication state is staged before a pre-terminal failure | Clear completes before rejection/cleanup state is staged and only the permitted cleanup is committed | Return a bounded, redacted rejection; retain transient retryability |
| Conflict retry | A failed attempt staged state and a concurrent winner changed durable state | Clear every failed attempt, rehydrate the winning state, and commit no stale attempt value | Exhaust only the configured budget |
| Conflict exhaustion | Final failed attempt contains staged values | Clear before cleanup/save; leave stream data unchanged and no terminal idempotency/publication residue | Return the existing redacted concurrency rejection |
| Advisory dead-letter failure | Dead-letter returns failure or throws after the primary failure | Continue only where the bounded contract permits; never restore discarded staged state | Preserve and classify the primary cause plus the advisory failure without payload disclosure |
| Remediation failure | Clear, checkpoint, cleanup, rejection save, or pending final save fails | Prevent a later save from silently committing residual state and report the actual durable consequence | Never claim staged state was discarded unless inspection proves it |

**Acceptance Criteria:**
- Given concrete stream and auxiliary values are staged before rehydration, domain-service, or event-persistence failure, when rejection completes, then clear precedes every rejection checkpoint, cleanup, dead-letter outcome, or save and no staged stream value reaches durable state.
- Given one or more persistence conflicts, when the actor retries or exhausts its budget, then each attempt clears before rehydration/restaging and only winning or pre-existing durable values remain.
- Given clear, dead-letter, checkpoint, cleanup, rejection-save, or finalizer-save failure, when the command terminates, then the earliest causal failure and observed durable consequence remain support-safe and no unproved discard is reported.
- Given any terminal Story 5.1 lane, when state is inspected through a fresh view, then original event/metadata keys are unchanged, only permitted rejection cleanup is observable, and no snapshot, publication index, drain, trigger, idempotency, or pending-count residue leaked.
- Given a cache clear cannot prove discard, when the same activation receives any later state-bearing turn, then it performs no state mutation or save until a clean-cache barrier succeeds, so residual mutations cannot hitchhike onto later work.
- Given a cache clear cannot prove discard, when any later state read or reconciliation runs on that activation, then it crosses the same barrier before consulting actor state and cannot expose a pending failed-attempt value as durable.
- Given initial Processing admission, stale-Processing takeover, or PublishFailed recovery save fails before commit or commits and then throws, when the command unwinds, then fresh inspection decides whether this command owns a durable pending slot or publication recovery; another command's slot is never decremented and no failed batch remains cached.
- Given legacy migration/redirect, stale-checkpoint handoff, or manual snapshot persistence fails, when the bounded result or exception returns, then a non-cancelable discard has completed or the activation is poisoned; an observed post-commit value is classified without being mistaken for cached residue.
- Given an ambiguous legacy-migration save, when fresh inspection observes the exact migrated record, then both `Terminal` and `Recoverable` dispositions resume their existing duplicate/recovery result instead of rethrowing a save failure that committed.
- Given stale-checkpoint handoff adds a missing publication-recovery owner or removes a zero-event checkpoint, when its batch commits, then `pending_command_count` equals the normalized distinct committed owner count in that same batch; it neither omits the new owner nor decrements an unrelated one.
- Given a pending-count read fails during admission, when recovery owners may already exist, then the turn performs no counter/pipeline save from a guessed zero value and completes discard/poison handling before propagating or returning the existing bounded infrastructure outcome.
- Given a finalizer save commits and then throws or fails before commit, when remediation inspects durable pending state, then it neither double-decrements nor strands a recoverable pending slot and reports an unambiguous observed consequence.
- Given a finalizer failure is followed by actor deactivation, when the next activation completes recovery, then `pending_command_count` is reconciled to the committed publication index before any actor state API can proceed; activation degradation leaves a mandatory first-turn retry rather than silently losing the obligation.
- Given terminal index repair, finalizer repair, and general reconciliation are simultaneously pending, when one obligation succeeds, then only that obligation is cleared and every independent obligation still blocks state access until its own durable invariant is proved.
- Given a reminder save commits and then throws, when fresh inspection proves drain cleanup or retry/stamp state committed, then cleanup side effects still complete and already-committed state is not redundantly saved again.
- Given caller cancellation reaches conflict clearing or dead-letter publication, when the path terminates, then cancellation propagates after non-cancelable state-safety cleanup and is not reclassified as advisory or remediation failure.
- Given remediation or finalization diagnostics are emitted, when focused tests inspect activities and structured logs, then stage, operation, exception type, discard/observation fields, and redaction are exact and no raw secret appears.
- Given implementation is complete, when focused tests, the full Server test project, and the Release solution build run, then all pass without warnings or regressions and every changed production await uses `ConfigureAwait(false)`.

## Design Notes

Use the deterministic `InMemoryStateManager` pending/committed model as the completion-grade durable-state oracle because the story gate names focused Server tests and a Release build, not a live-sidecar lane. A test-local wrapper should add fault scheduling and operation order without widening the public Testing package. Treat normal infrastructure rejection as advisory status plus durable pipeline cleanup; do not invent a retained `Rejected` pipeline record where checkpoint and removal share one batch.

The pinned Dapr Actors 1.18.5 `Actor`/`ActorHost` surface has no immediate self-deactivation API. Maintain an activation-local unsafe-cache flag after any failed discard. After tenant validation where applicable, every external actor entry point that consults actor state -- reads, reconciliation/inspection, command processing, redirect mutation, snapshot creation, and reminders -- crosses one non-cancelable barrier before its first state access. On barrier failure, fail closed without reading, staging, or saving and keep the flag set. A helper that converts a state failure into a bounded result (notably legacy redirect `Unavailable` and manual snapshot `InfrastructureFailure`) must first complete that same discard/poison protocol; a returned status is never evidence the cache is clean.

No local flag written before `SaveStateAsync` returns proves durable ownership. Protect legacy migration, stale-checkpoint handoff/cleanup, initial Processing admission, and PublishFailed recovery at their actual save sites. After a save exception, clear first and inspect the batch's durable witnesses: exact pipeline identity plus pending count for Processing admission/takeover; pipeline removal and normalized owner count for stale cleanup/handoff; and the committed publication index/drain/idempotency state for PublishFailed recovery. A pre-commit Processing failure owns no slot and must not decrement the prior count; a commit-then-throw owns the observed slot and may finalize it. An exact migrated idempotency witness is authoritative for either Terminal or Recoverable disposition. PublishFailed always retains the slot when the already-committed publication index proves recovery remains outstanding, but its failed recovery batch must still be discarded so staged drain/idempotency changes cannot hitchhike.

For pending-count finalization, establish the committed pre-decrement count after a clean clear. If save fails, clear and inspect durable state: an already-decremented value proves commit-then-throw; the unchanged value permits one clean recovery decrement/save; any other value or failed inspection keeps the activation unsafe and is reported without another save. Exercise both pre-commit and commit-then-throw failure of that repair save. Record the exception type of a failed discard attempt separately from the original remediation operation so `FailedBatchDiscarded=false` is diagnosable without raw messages; once a clear completed, a later inspection failure must not relabel that discard as unproved. Finalizer repair state and general index/counter reconciliation state are separate obligations. Clearing finalizer-local fields never clears the general reconciliation flag; only a fresh proof that the counter equals the normalized committed owner set clears the latter.

Activation memory is not durable recovery. Once publication recovery re-arm/pruning finishes, an idle activation reconciles `pending_command_count` to the freshly re-read committed index's normalized, well-formed, distinct message-owner count; at activation there is no executing command, so those owners are the durable outstanding publications. Normalize duplicate persisted message IDs before capacity and counter calculations so one owner counts once. If activation recovery degrades, retain an activation-local `reconciliation required` flag and make every later entry barrier retry reconciliation before any state API proceeds. Because reconciliation intentionally removes an orphaned Processing slot, a later command that adopts or replaces a committed `Processing` checkpoint must acquire and commit a fresh pending slot instead of assuming the old count survived. A stale committed handoff that adds a missing recovery owner must stage the resulting normalized owner count in the same atomic batch; zero-event cleanup stages the unchanged normalized owner count and never decrements blindly. Inspect after reconciliation-save failure to distinguish commit-then-throw, and never clear the obligation until the committed count equals the committed normalized owner count.

The historical backpressure read was fail-open for availability, but admission cannot safely persist `0 + 1` after the read failed because that can overwrite slots owned by committed recovery entries. On a failed pending-count read, do not stage a counter or Processing checkpoint from a guessed value. Complete non-cancelable discard/poison handling, then propagate or use the existing bounded infrastructure result without adding a new public contract. This narrows only the unsafe mutation after a failed read; successful backpressure thresholds and result fields remain unchanged.

Manual snapshot and legacy redirect failures use their existing public result types. Clear cached state before returning a failure; after an ambiguous save, inspect the exact snapshot/redirect key to report or return the observed bounded consequence, and poison the activation when neither discard nor observation succeeds. Stale-handoff failures may keep their existing fail-closed command result only after cached mutations are discarded or the turn is converted to a remediation exception.

Reminder ambiguity follows the same durable-witness rule through the full consequence. If a drain-success batch committed and then threw, the missing committed drain record proves cleanup; continue reminder unregistration and terminal advisory status rather than returning early with a permanent `PublishFailed` view. If the retry record already contains the attempted increment, use it directly for diagnostics/status and do not stage or save it a second time. Reminder-stamp and activation-reconciliation saves require pre-commit and commit-then-throw tests. The non-transactional dead-letter marker behavior and dead-letter retry policy remain unchanged by this story.

Propagate caller/request cancellation from conflict clearing, stale-checkpoint handoff, and dead-letter publication after required non-cancelable cleanup; non-cancellation publication failures remain advisory. Preserve the prior finalizer cancellation contract after best-effort discard. Mark the relevant child and process activities failed whenever remediation escapes, and verify all structured diagnostic fields and redaction.
