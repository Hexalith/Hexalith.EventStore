## Intent

**Problem:** EventStore, Admin.Server, and the external sample API accept incomplete or unsafe non-Development JWT configuration, do not constrain accepted signing algorithms, and disagree about multi-audience configuration. Committed development settings, Keycloak users, fixtures, scripts, and documentation also publish reusable material capable of minting privileged tokens.

**Approach:** Establish one fail-closed JWT configuration contract across public hosts, wire AppHost run/publish models through it, generate local credentials per run, and enforce a repository-level tracked-content guard that permits inert placeholders but rejects forgeable credentials and signing material.

## Boundaries & Constraints

**Always:** Require exactly one of Authority or SigningKey; require non-blank issuer and at least one non-blank audience; validate issuer, all configured audiences, signature, expiration, lifetime, and an explicit algorithm allow-list; require an absolute authority without userinfo/query/fragment and HTTPS metadata outside Development; generate local signing keys and Keycloak passwords cryptographically per run; log an explicit support-safe warning when a permitted non-Production symmetric exception is active; keep real OIDC and probe behavior testable.

**Never:** Permit symmetric JWT validation in Production even when the legacy override is set; allow a non-Development HTTP authority or disabled HTTPS metadata; silently prefer Authority when SigningKey is also present; default issuer/audience, privileged subject, password, or administrator claims outside Development; commit usable keys, passwords, tokens, decoded JWT payloads, or privileged fixture credentials; expose generated secret values in logs/evidence; implement Story 5.2 authorization, Story 5.4 Admin hygiene/OpenAPI gating, Story 5.5 internal trust, general Story 5.6 topology work, Story 5.9 deployment alignment, Story 7.6 OpenBao retrieval, or modify `sprint-status.yaml`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|---------------|---------------------------|----------------|
| Production OIDC | One absolute HTTPS Authority, HTTPS metadata, issuer, audiences, no key | Host starts and accepts only configured issuer/audience/algorithms | Invalid or incomplete configuration fails during startup before serving |
| Unsafe authority | Blank/relative/HTTP/userinfo/query/fragment Authority, or HTTPS metadata disabled outside Development | Configuration is rejected | Failure names the setting, never a secret value |
| Ambiguous mode | Authority and SigningKey both configured | Configuration is rejected | No precedence fallback |
| Symmetric mode | Development, or explicit non-Production exception, with a random 32-byte-or-stronger key | HS256 only; exception emits a redacted warning | Production and unapproved non-Development use fail startup |
| Token validation | Missing expiry/signature, wrong issuer/audience/key, or algorithm outside the mode allow-list | Authentication fails before protected work | Existing bounded/redacted 401 contract remains |
| Local topology | Keycloak enabled or disabled during `aspire run` | Per-run credentials are shared only through resource environment; no committed fallback | Missing runtime inputs fail closed without printing values |
| Repository guard | Tracked source/config/docs/scripts/fixtures contain real secrets versus documented placeholder syntax | Placeholders pass; usable material fails with path/line only | Generated/build/VCS content is excluded explicitly, never by broad test-folder exemption |

## Design Notes

The shared contract belongs in ServiceDefaults because EventStore.Gateway, Admin.Server.Host, and the external sample API already depend on it. Host-specific wrappers may preserve existing option names, logging, and challenge behavior, but they must delegate security decisions to one implementation. Runtime audience binding must use a first-class `ValidAudiences` collection rather than environment keys targeting a `TokenValidationParameters` instance that the configurers replace. `AllowedAlgorithms` is a first-class configuration collection: authority mode requires a nonempty caller-supplied subset of supported asymmetric algorithms and never invents a default; symmetric modes ignore/reject asymmetric configuration and accept HS256 only. Assign defensive copies to framework option objects.

Local Keycloak realm content may retain non-secret claims needed for authorization tests, but password and subject/bootstrap identifiers are template inputs resolved once per AppHost run. The no-Keycloak development path uses the same generated HS256 key for token issuers and validators, including Aspire integration fixtures. Secret-bearing directories/files are created with their final restrictive modes before bytes are written and are owned by a cleanup scope that begins immediately after render. Repository scanning is Git-tracked-content and syntax aware: configuration key names, `${NAME}`, `{env:NAME}`, `<token>`, and deliberately malformed sentinels are inert only when they match exact recognized forms; broad path/extension exclusions, minimum-secret lengths, value-prefix shortcuts, punctuation shortcuts, and fixed “dev-only” secret exceptions are not.

Publish mode represents external production identity only. It canonicalizes the first nonblank configured audience when no primary is present, preserves the remaining audiences, and propagates the explicit algorithm list to accepting hosts. Published UIs receive separate sample/Admin credential parameter resources plus a provider-neutral token endpoint (explicit HTTPS configuration or OIDC discovery) and explicit scope/audience request configuration; password/key bytes are opaque, and blank token responses fail. The legacy Aspire client-credential call shape remains source-compatible for root-declared consumers by resolving nonliteral parameter resources rather than restoring default usernames/passwords. Local run mode may use dynamic Keycloak ports and documentation must show how to discover the actual endpoint. All three default probes carry explicit anonymous metadata even if a fallback policy is later introduced; Production real-host evidence couples their bounded responses with a protected-work negative control.

Realm rendering substitutes every placeholder in one pass from the original JSON. A live owner lease distinguishes an active run from stale owned content, and ownership begins at successful render so normal disposal and post-render model-construction failures clean the directory. The production AppHost never accepts persistent local credential overrides; any injection seam exists only for isolated test invocations whose fixtures generate fresh values. Tests parse the rendered JSON and inspect actual AppHost run/publish model environment callbacks and parameter secret metadata.

Normal AppHost startup never reads or creates the capability that authorizes deterministic test credentials. Tests invoke an internal overload with a fresh caller-held capability and matching isolated values; an arbitrary configuration GUID is insufficient. Realm ownership rejects symlink/reparse-point roots before mutation, records exactly which files it creates, removes its secret files even if unrelated content appears, deletes the marker last, and changes its disposed state only after successful cleanup so transient failures can be retried. Any residual `__HEXALITH_` prefix is a render failure even when it is not a well-formed known placeholder.

Outgoing UI token acquisition is explicit rather than universally labeled provider-neutral. The configured authority is always normalized and validated. Discovery must contain both a matching normalized `issuer` and a valid token endpoint. A `password` profile sends client id, username, opaque password, and scope; a `client_credentials` profile sends client id, opaque client secret, and scope. Neither sends `audience` implicitly: an optional configuration pair supplies the provider-specific parameter name and value together. All endpoint/profile inputs are resolved before an Aspire resource is mutated. Distinct sample/Admin model tests resolve the actual parameter references and secret annotations.

The tracked-content guard decodes supported UTF-8/UTF-16 text, scans its own source plus tracked tooling/artifact trees, and exempts only explicit inert placeholders or grammar-proven nonliteral references. Adversarial literals are constructed at test runtime. Identifier equality, colon shape, shell default operators, file location, and assignment punctuation never establish inertness. Detection covers underscore/hyphen names, raw and multiline assignments, bearer/opaque tokens, structurally decoded JWT payloads, and any PEM block whose label denotes a private key.

Scanner recognition is structural: it parses decoded JSON to identify JWT claim objects recursively, parses C# raw-string delimiters, rejects calls composed only of literals, recognizes credential URI userinfo and common generic/suffixed environment names, and scans recoverable text spans after malformed bytes without treating arbitrary binary blobs as text. Bearer recognition covers header assignments, standalone scheme values, and common authentication-header constructors with the full bearer-token alphabet and no length threshold. Historical evidence is never made truthful by editing a hashed capture in place; use the governed capture/lineage path to supersede it or explicitly retire it.
