## Intent

**Problem:** NFR13/OR26 require the REST source-generator package and its generated controllers to build with zero warnings under warnings-as-errors and to follow EventStore code style, nullable, ULID and `ConfigureAwait(false)` rules. A bound CI command must fail on a seeded violation of each rule. Today the generator tests fail only on errors, and the generator project builds without code-style enforcement. Analyzers also skip `<auto-generated />` output. Style, CA2007 and Guid-parsing regressions in emitted code would therefore pass CI.

**Approach:** Keep emitter and generator behaviour unchanged: a probe on 2026-11-07 found zero violations. Add only the missing gates:
1. A `Generators.Tests` conformance class over representative fixtures. It fails on any warning in generated trees, a missing `#nullable enable`, an `await` without `.ConfigureAwait(false)`, or any `System.Guid` parse call. Each rule has a seeded-violation test.
2. `EnforceCodeStyleInBuild` on the generator project.
3. A conformance project that compiles a copy of Sample.Api's emitted controllers as ordinary code with the real analyzers.

The bound commands are CI's existing Release `-warnaserror` solution build and the `Generators.Tests` run.

**Decisions (owner, 2026-11-07):**
- Generated-output code style is proven by option B: a non-packable conformance project. Sample.Api emits its generated files. The project compiles copies of the REST-generator files with `generated_code = false`, `EnforceCodeStyleInBuild` and the repository `.editorconfig`, inside CI's existing solution build. Code-style seeding is proven by a recorded local mutation, not a permanent test. The rejected options were analyzers loaded in-test (A) and exempting generated output (C).
- The full spec is kept, at about 2,000 tokens over the 1,600 guideline.

## Boundaries & Constraints

**Always:**
- Reuse `RestApiGeneratorTestHarness` and the existing fixtures.
- Checks fail closed: zero generated sources or zero scanned awaits is a failure.
- Seeded violations mutate real generated text.
- If a gate exposes a real violation, fix the emitter, not the gate.
- Stage named paths only.

**Never:**
- Byte-stable or deterministic generator output.
- Emitter behaviour or public API changes beyond such fixes.
- Warning suppression, `NoWarn` or lowered severities.
- Repository-wide `EnforceCodeStyleInBuild`.
- Edits to Hexalith.Builds or CI workflows, or new CI lanes.
- Tenants host changes, BannedApiAnalyzers, new packages, or committed evidence.

## Spec Change Log

- 2026-11-07, implementation finding: `EnforceCodeStyleInBuild` alone did not gate the generator. The SDK derives no `AnalysisLevel` for `netstandard2.0`, so the build left `EffectiveAnalysisLevelStyle` empty and ignored the `.editorconfig` `option = value:warning` severities. A seeded block-scoped namespace (IDE0161) and a using inside the namespace (IDE0065) both built with 0 warnings. The net10.0 conformance project was not affected, because it gets level `10.0`. Fix: `<AnalysisLevelStyle>latest</AnalysisLevelStyle>` on the generator project only. This is the documented switch that makes builds honour those severities. It brings in the SDK's `Default` style global config, which configures nothing (`global_level = -99`). It suppresses nothing and is not repository-wide. The generator source still builds with 0 warnings, and both seeds now fail (see Verification).
- 2026-11-07, fixture reuse: `ReferencedTenantsContractHostSource` also became `internal`. The bound-query fixture only generates a controller when compiled with its host source, so the new class reuses it rather than copying it. No existing test changed.
- 2026-11-07, conformance-project detail: Roslyn discovers `.editorconfig` files only from evaluation-time `Compile` items. This project has no sources of its own, so its copy target also adds the `.editorconfig` files above the copies to `EditorConfigFiles`. The Csc invocation was checked to receive the repository and project `.editorconfig` files and the SDK CodeStyle and .NET analyzers.
