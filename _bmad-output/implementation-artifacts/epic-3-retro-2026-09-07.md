### AGG-8 — MEDIUM — Two independent implementations of the "platform-owned, versioned evidence codec"

**Source.** `tools/deployed_runtime_parity_handlers/v1.py` (1,139 lines) and
`tools/release_evidence_handlers/v3.py` (1,055 lines) share **11** top-level function names of

Story 3.15 and must not be edited, so consolidation needs its own authorized story.
**Upstream lesson.** The "one codec" decision was recorded in context prose but never enforced
by a test or an import boundary.

#### Verified findings

These were re-checked against the files and hold. Line numbers below are this retro's, and
supersede a lens's where they differed.

**DSR-1 [verified] — `deployed_runtime_parity` is a constant, not a verdict.**
`assemble-corrected-deployed-runtime-parity.py:324` writes the literal
`"deployed_runtime_parity": "available"`; `deployed_runtime_parity_handlers/v1.py:401` expects
that literal in `_expected_subject`, `:437` lists it as a required key, and `:599` is the guard
`document["deployed_runtime_parity"] != "available"`. The schema has no representable
"unavailable" verdict, so the guard **cannot fail on any packet this producer emits**. The
team saw the unconditional write — `assemble:277` carries the comment about it — and hardened
only the smoke precondition, leaving the field constant. *Green by construction.*

**DSR-2 [verified] — `observed_runtime_platform` observes image metadata, not a runtime.**
`capture-corrected-deployed-runtime-parity-smokes.py:258` reads
`docker image inspect --format {{.Os}}/{{.Architecture}}` and `:300` records it as
`observed_runtime_platform`; `v1.py:804` then asserts
`item["observed_runtime_platform"] != item["platform"]`. Both sides derive from the image's own
declared metadata after `docker pull --platform` already selected it, so the comparison is an
artifact validating its own claim. The one field that makes this deployed-**runtime** parity
rather than registry-metadata parity is decorative. *Green by construction.*

**DSR-3 [verified] — the producing codec and the validating codec are different programs.**
The frozen Story 3.14 packet declares its producer as
`successful/tools/release_evidence_codec.py`, sha `814502bd…`, **41,113 bytes**
(`evidence/story-3-14/f343bb01…/release-identity.json`, `codec.codec`). The live handler that
revalidates it is `tools/release_evidence_handlers/v3.py`, sha `b1a17562…`, **48,654 bytes**.
`v3.py:15` declares `EXPECTED_PACKET_CODEC_SHA256 = "814502bd…"` and `:216` checks the packet's
declared digest against that literal — so the check compares the packet's claim to a constant
living inside the drifted file. `validate-corrective-release-evidence.py:26,203` then compares
that constant to *another* repo-authored constant. Nothing anywhere compares producing bytes to
validating bytes.

**DSR-4 [verified] — the retained verifier's digest is never pinned, only its path.**
`v3.py:216-218` pins `codec_binding["sha256"]` against `EXPECTED_PACKET_CODEC_SHA256` but for
the verifier checks only `verifier_binding["file"] != RETAINED_VERIFIER_FILE`. There is no
`EXPECTED_PACKET_VERIFIER_SHA256`. The retained verifier bytes are self-consistent but
unreviewed.

**DSR-5 [verified] — the assembler's "executing from the repository" guard is tautological.**
`assemble-corrected-deployed-runtime-parity.py:113` defines
`repository_root() = Path(__file__).resolve().parents[1]`, and `executing_assembler_path`
(`:117-129`) then asserts `Path(__file__).resolve() == (root / v1.ASSEMBLER_FILE).resolve()`.
Both sides derive from `__file__`, so the identity holds for **any** copy of the script in any
directory named `tools`. Its own docstring claims it catches "a copy executed from elsewhere";
it catches only a rename or a move out of `tools/`. *Green by construction.*

**DSR-6 [verified] — `canonical_bytes` is not one function.**
`v1.py:225` and `capture…smokes.py:60` both pass `allow_nan=False`;
`release_evidence_handlers/v3.py` passes it **nowhere** (`grep -n allow_nan` returns no hit in
that file). A document containing `NaN`/`Infinity` therefore round-trips unchanged through v3's
canonical-bytes identity check while making v1 raise. This is the concrete divergence behind
AGG-8: "canonical" means two different things inside one trust chain.

**DSR-7 [verified] — `tools/release_evidence_codec.py` is an unpinned star-import facade.**
The 11-line file re-exports v3 via `from …release_evidence_handlers.v3 import *` inside a broad
`except ImportError`. Consequences, all checked: `import *` drops every `_`-prefixed helper
despite the docstring's claim that direct importers "keep their historical API"; there is no
`__all__`; the broad `except` would misdiagnose an `ImportError` raised *inside* v3 as a layout
problem; and the file appears in **neither** `validate-corrective-release-evidence.py`'s
`HANDLER_FILE_SHA256` nor `validate-corrected-deployed-runtime-parity.py`'s
`IMPORT_PATH_FILE_SHA256`, so importing through it executes v3 with no digest pin at all.

**DSR-8 [verified] — the release gate has a one-checkbox downgrade to a message linter.**
`release.yml:9` declares a `bypass-validation` dispatch input; `:36` reads it and `:48` sets
`source_ci_workflow="commitlint.yml"`. `commitlint.yml` builds and tests nothing. With that box
ticked, publication to NuGet and the container registry proceeds on a commit-message lint as
its source proof. Nothing restricts who may set it or requires CI to have also passed. *This is
the input that project memory records as intended for removal once
`require-publication-authority` became the opt-in mechanism; it survived.*
