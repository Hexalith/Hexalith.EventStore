Accessibility & support-safety review

review-accessibility-support-safety.md

The spines are strong exactly where the memlog says the stakes are: accepted is never success, LocalOnly/Unknown never masquerade as confirmed, denied never confirms existence, deferred work is hidden/disabled/501, raw internals are banned from every surface, and the four 2026-07-05 findings (localization evidence, mobile mutation policy, denied-state focus/copy, live-region priority) are now answered in EXPERIENCE.md. What would bite a real operator is the layer *around* those rules: the spines never say who the audited actor is or show it before a confirm, never bound the "evidence pending" wait or forbid resubmitting a late-but-not-failed mutation, never map server outcomes (401/403/404/501/network) to distinct operator-visible states, and never regulate the two channels that most easily fake success or flood assistive tech: toasts and auto-refresh. Localization is answered at the string level but is silent on timestamps, time zones, plurals, invariant lifecycle codes, and text expansion. The two HTML mocks are honest about state semantics but contradict the spines on keyboard operability, legacy Fluent v4 tokens, and a decorative success-coloured banner; anyone copying their markup ships an inaccessible tab strip.

WCAG floor

high

Live-region priority is classified but placement, scoping, and throttling are not

EXPERIENCE.md:172-180, EXPERIENCE.md:151
With polling plus SignalR nudges, every "polite" stale/current flip on every stat card and every lifecycle step of every in-flight command (Overview mock shows 7 in flight, dashboard-overview.html:298) becomes an announcement; a screen-reader operator in an incident gets a continuous stream. Nothing says a grid re-render must not re-announce rows.
Fix: one status region per dashboard view; announce only (a) transitions of the operation the user initiated and (b) terminal states; background refresh announces at most one summary per cycle ("Evidence refreshed, 3 rows changed") and only when something changed; never announce per-row lifecycle steps from a grid.
high

Auto-refresh has no cadence, no pause, and no state-preservation rule

EXPERIENCE.md:151, EXPERIENCE.md:116, EXPERIENCE.md:115
WCAG 2.2.1/2.2.2 require a way to pause or extend auto-updating content; the spine only says "polling remains fallback". Nothing says a poll must not reset grid sort/selection/scroll, collapse an accordion, close a drawer, or replace the row an operator is reading in a confirmation dialog. Legacy code already polls on a 30 s PeriodicTimer (src/Hexalith.EventStore.Admin.UI/Pages/DaprPubSub.razor:408), so implementers will carry that forward unguided.
Fix: declare the polling interval and expose it with a pause/resume control in the dashboard header; refresh must preserve focus, selection, scroll, expanded sections, and open dialogs; a dialog's target facts are frozen at open time and a changed underlying row surfaces as a conflict (see Silences), not as a silent swap.
medium

Focus destinations are ambiguous for tab activation, deep links, and non-modal detail panels

EXPERIENCE.md:162, EXPERIENCE.md:150, EXPERIENCE.md:168, EXPERIENCE.md:102
"One focusable page title per selected tab" can be read as "move focus to the title on tab change", which breaks arrow-key traversal of FluentTabs; deep-link entry says only "select the right tab/detail"; focus return is specified for dialogs but not for FluentDrawer detail panels, which are not modal and so have no implicit return.
Fix: user tab activation keeps focus on the tab; route/deep-link entry focuses the page title; opening a detail panel moves focus to the panel heading; closing it returns focus to the originating row/control; state this for drawers explicitly.
medium

Row-click is the only stated drill-in affordance and icon-only header actions have no naming rule

EXPERIENCE.md:98, DESIGN.md:218, DESIGN.md:105
A <tr> click handler is not keyboard-operable; "small utility actions" in a 44 px app bar are likely icon-only. WCAG 2.5.8 (24×24 minimum) is not mentioned anywhere.
Fix: every evidence row exposes a focusable open action (or FluentDataGrid row activation via Enter/Space); icon-only controls carry an accessible name and a ≥24 px target; add the target-size floor to DESIGN.md.Components.
medium

Contrast target covers text only; disabled-with-reason has no discoverability rule

DESIGN.md:178, DESIGN.md:32, EXPERIENCE.md:213-214
No 3:1 non-text target for badge borders, focus ring on the accent app bar, or lifecycle-tracker fills. "Disabled with stale/unknown reason" is the primary safety pattern, yet disabled controls are contrast-exempt and their title/tooltip is not keyboard-reachable, so the *reason* — the thing that keeps the operator from escalating wrongly — can be invisible to keyboard and screen-reader users.
Fix: add a 3:1 non-text contrast target; require the disable reason to render as adjacent enabled text (or a FluentMessageBar) associated via aria-describedby, not only as a tooltip.
low

Narrow reflow stops at "< 960px" and skeleton motion is unregulated

EXPERIENCE.md:191-195, EXPERIENCE.md:113, EXPERIENCE.md:169, command-investigation.html:131
No 320 px / 400 % zoom rule; scrolling tab strips must keep the active tab visible and reachable; the mock's minmax(480px,…) grid cannot reflow. Reduced motion is scoped to "state changes", which does not obviously cover shimmering skeletons.
Fix: state that grids scroll inside their own container or stack at ≤ 400 px, tabs overflow to a menu, and skeleton shimmer honours prefers-reduced-motion.

Localization

high

No rule for date, time, time-zone, duration, or number rendering

EXPERIENCE.md:182-187, DESIGN.md:186, dashboard-overview.html:281, dashboard-overview.html:320, command-investigation.html:276
Mocks show bare 08:24:12 and one 08:24 UTC; legacy pages format with ToString("HH:mm") in the server culture (src/Hexalith.EventStore.Admin.UI/Components/StreamTimelineGrid.razor:70). Operators correlate timestamps across tools during incidents; UTC/local ambiguity is a real support hazard, and "12s" lag is a hand-built string.
Fix: all timestamps render absolute with an explicit zone (operations default UTC, optionally the user's zone as secondary) plus a relative age; numbers/durations go through culture-aware, resource-backed formatters; add this to Localization evidence.
medium

Lifecycle and freshness codes are used both as enums and as visible labels with no invariant/translated split

EXPERIENCE.md:104-105, command-investigation.html:272, command-investigation.html:296-300
If EventsStored, LocalOnly, Unknown are translated, cross-language support handoff breaks (a French operator quotes a label the English on-call cannot grep); if they are not translated, the "all copy resource-backed" rule is violated.
Fix: render a localized label plus the invariant code (monospace, never translated), and list which tokens are invariant identifiers.
medium

Pluralization has a prohibition but no mechanism

EXPERIENCE.md:185, EXPERIENCE.md:121, EXPERIENCE.md:142
Counts appear everywhere (dead letters, rows updated, retries).
Fix: name the mechanism — per-plural-category resource keys or a shared plural formatter — and forbid count + " items" patterns in the conformance checklist.
medium

RTL, text expansion, and truncation are silent

EXPERIENCE.md:194, DESIGN.md:200, dashboard-overview.html:318
Nine tabs already scroll at 960–1279 px; a 30 % expansion (FR/DE) pushes "Storage & Snapshots"/"Deferred & Backlog" and lifecycle step names into truncation with no rule for exposing the full text. The mock truncates aggregate ids to 01JZ4... with no accessible full value.
Fix: state the RTL stance (Fluent dir mirroring, identifiers stay LTR), a 30 % expansion tolerance for tabs/badges/tracker steps, and a truncation rule: full value always available via accessible name or a copy action.
medium

Server error text passthrough is not governed
