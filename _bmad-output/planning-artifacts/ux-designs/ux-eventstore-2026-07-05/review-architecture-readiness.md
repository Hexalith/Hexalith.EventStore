# Architecture & Readiness Review — eventstore

Reviewed: 2026-09-08 against spines updated 2026-08-01. Read-only code inspection of
`src/Hexalith.EventStore.Admin.UI`, `src/Hexalith.EventStore.AppHost`,
`samples/Hexalith.EventStore.Sample.BlazorUI`, `references/Hexalith.Tenants/src/Hexalith.Tenants.UI`,
`references/Hexalith.FrontComposer`, and the planning artifacts after the 2026-08-01 story-ID migration.

## Preamble

The spines are architecturally aligned on the decisions that matter: in-place evolution of `Admin.UI` under `eventstore-admin-ui` (verified in `src/Hexalith.EventStore.AppHost/Program.cs:94` and the csproj `ContainerRepository`), one `event-store-admin` module entry, projection-confirmed success, AD-15 provenance vocabulary that matches `QueryResponseProvenance` / `ProjectionLifecycleState` exactly, an eight-stage command tracker that matches `CommandStatus` exactly, and honest deferred operations. `ux.md`, `index.md`, and the epics hash pins are consistent, and the 2026-08-01 correction is fully reflected in EXPERIENCE/DESIGN. What would mislead a story-dev is one layer below: the tab map silently drops a live route (`/types`), both HTML mocks and DESIGN.md's color roles are written in the Fluent v4/FAST token vocabulary the project policy bans, the Admin dashboard's "projection freshness indicator" has no data source in the Admin transport, and the FrontComposer composition the spines assume (packages, registry API, catalog entry) is neither present in the host nor described. None of this is unfixable, but a dev building Story 7.14 from the spine as written would produce a ten-tab dashboard that loses the Type Catalog and could not populate the freshness states the spine mandates on the Projections and Commands tabs.

## Findings

### IA vs code

- **[high]** Tab map omits the live `/types` route (`EXPERIENCE.md:39-50`; `src/Hexalith.EventStore.Admin.UI/Pages/TypeCatalog.razor:1`; `Layout/NavMenu.razor:17`; `Components/CommandPaletteCatalog.cs:24`). Code has 22 `@page` templates; the spine's "Legacy source routes" column lists 21, and the same 21 are copied into Story 7.14's route-manifest AC (`epics.md:5573-5576`) and UX-DR3/UX-DR4 (`epics.md:190-192`). The IA closure rule at `EXPERIENCE.md:54` ("every legacy Admin.UI feature has a target EventStore tab") is therefore false today, and Epic 6 stories explicitly expect a Type Catalog surface (`epics.md:4522`, `4602`, `4665`). A dev following the manifest literally will either drop the Type Catalog or invent an unowned tab. *Fix:* add `/types` to the tab map (Streams & Events or a "Types" sub-surface under Projections/Topology), state its detail-panel disposition, and propagate to UX-DR4 and the 7.14 manifest list.
- **[medium]** "Topology" is already a name in the code with a different meaning (`Layout/NavMenu.razor:29-56`). The existing `FluentNavCategory Title="Topology"` is a dynamic tenant→domain stream navigator that deep-links to `/streams?tenant=&domain=`; the spine's Topology tab is DAPR/services (`EXPERIENCE.md:46`). The spine does not say where the tenant/domain navigator goes (Streams & Events filter bar? dropped?). *Fix:* name the disposition of the existing tenant/domain navigator and rename the DAPR tab or the navigator to avoid two "Topology" concepts during migration.
- **[medium]** `/health` is placed under Recovery, but the code's Health page is a DAPR component-status dashboard (`EXPERIENCE.md:48`; `Components/CommandPaletteCatalog.cs:14-15` maps "DAPR Component Status" and "Observability Tools" to `/health`). The same content family is assigned to Topology via `/dapr/health-history`. *Fix:* split explicitly — component health → Topology, overall health summary + dead letters + consistency → Recovery — and say which page owns the shared components.
- **[low]** Host title and label diverge: the shell renders "Hexalith EventStore Admin" (`Layout/MainLayout.razor:23`) while the spine mandates label **Event Store Admin** (`EXPERIENCE.md:92`; `DESIGN.md:72`). Breadcrumb (`Layout/Breadcrumb.razor`) and the dev role switcher (`MainLayout.razor:26-38`) are not mentioned by the spine at all. *Fix:* state whether breadcrumbs survive under tabs and that the dev role switcher is a non-production utility outside the header contract.
- **[low]** Existing narrow-screen behaviour contradicts the spine and is not called out as a removal obligation (`MainLayout.razor:49-51`, `wwwroot/css/app.css:235-296`: a `role="alert"` banner "Dashboard optimized for wider screens."). The spine's `<960px` band promises usable triage (`EXPERIENCE.md:195`). *Fix:* add a one-line "existing behaviour to retire" note so 7.20 does not inherit it as acceptable.

### Platform constraints

- **[high]** Both HTML mocks are built on banned Fluent v4/FAST tokens (`mockups/dashboard-overview.html:16-27`, `mockups/command-investigation.html:16-26`: `--accent-fill-rest`, `--neutral-layer-1`, `--neutral-layer-2`, `--neutral-foreground-rest`, `--neutral-foreground-hint`, `--neutral-stroke-rest`, `--neutral-fill-rest`, `--neutral-fill-layer-rest`, `--neutral-fill-stealth-rest`, `--neutral-fill-strong-rest`). The policy forbids exactly these families (`references/Hexalith.AI.Tools/hexalith-ux-instructions.md:31-33`), as do `DESIGN.md:180` and UX-DR6 (`epics.md:200`). The spines link the mocks as visual references (`DESIGN.md:166`, `EXPERIENCE.md:25`, `index.md`), so a dev who opens them for CSS will copy the wrong tokens. *Fix:* re-express the mock variables with Fluent 2 tokens (`--colorBrandBackground`, `--colorNeutralBackground1/2`, `--colorNeutralForeground1/2`, `--colorNeutralStroke1`, `--colorNeutralBackground3`) or add a banner comment in each mock stating the tokens are illustrative only and must not be copied.
- **[medium]** DESIGN.md's colour roles are named in the v4/FAST recipe vocabulary (`DESIGN.md:15-32`: "accentFill", "foregroundOnAccent", "neutralLayer1", "neutralLayer2", "neutralForegroundHint", "neutralStroke", "neutralFill", "neutralFillLayer", "focusStroke"). These are FAST design-token names; Fluent 2 (V5) roles are `colorBrandBackground`, `colorNeutralForegroundOnBrand`, `colorNeutralBackground1/2/3`, `colorNeutralForeground2/3`, `colorNeutralStroke1`, `colorStrokeFocus2`. The prose says "do not use legacy Fluent v4/FAST tokens" (`DESIGN.md:180`) while the token table does. *Fix:* rename the `colors:` values to Fluent 2 role names (or to the V5 component parameter that yields them) so the table and the rule agree.
- **[medium]** `FluentBadge Color=Neutral` is not a V5 value (`DESIGN.md:30-31`, `114-115`, `143-147`). `BadgeColor` in Microsoft.FluentUI.AspNetCore.Components 5.0.0-rc.5 is `Brand, Danger, Important, Informative, Severe, Subtle, Success, Warning` (verified via the fluent-ui-blazor component catalog; the Tenants module uses `Subtle`/`Informative`, `references/Hexalith.Tenants/src/Hexalith.Tenants.UI/Components/Shared/ProjectionLifecycleBadge.razor:28-33`). *Fix:* replace `Neutral` with `Subtle` (or `Informative`) and note that `Appearance` (`Filled/Outline/Ghost/Tint`) is orthogonal to `Color`.
- **[medium]** `FluentDrawer` is cited as a detail-panel primitive (`DESIGN.md:128`, `DESIGN.md:226`; copied into UX-DR18 `epics.md:224`) but is **not found** in the V5 component catalog queried (rc.5 Dialog category lists only `FluentDialog`/`FluentDialogBody`/`FluentDialogProvider`); neither Tenants nor FrontComposer source uses it. Status: unverified — treat as unavailable until a V5 release note proves otherwise. *Fix:* list `FluentDialog` (panel-style) or the FrontComposer panel primitive as the detail-panel component and drop `FluentDrawer` unless a version is pinned that ships it.
- **[medium]** `FluentTabs` in V5 is a content-tab component, not a router, and its docs state there is no scroll behaviour for overflowing tabs. The spine requires URL-addressable tabs (`EXPERIENCE.md:95`, `150`) and horizontally scrolling tabs at 960-1279px (`EXPERIENCE.md:194`). Both need custom wiring/CSS the spine does not acknowledge, which collides with the "no raw CSS when a component exists" rule unless declared as layout-only CSS. *Fix:* state that tab selection is bound to the route (`ActiveTabId` ↔ URL segment) by the shell, and that tab-row overflow is an allowed layout-only CSS exception.
- **[low]** The existing custom status palette (`wwwroot/css/app.css:5-10`, `32-37`, `53-58`: `--hexalith-status-*`, `--hexalith-brand` hex values) and one v4 token in a Razor file (`Components/Shared/ProtectedContentPanel.razor:20`: `--neutral-stroke-rest`, `--neutral-layer-2`) are exactly what the policy requires to be tracked as an allowlisted migration backlog (`hexalith-ux-instructions.md:37-39`). Story 7.20's reconciliation names them (`epics.md:5927`); the spine does not. *Fix:* add a "legacy token inventory to retire" line in DESIGN.md Colors pointing at these files.
- **[low]** DESIGN.md sets an explicit heading ramp in px (`DESIGN.md:40-57`: page-title 34px/400, section-title 18px/600, metadata 12px) while also saying "Do not define a new heading ramp in CSS" (`DESIGN.md:188`). The policy wants `FluentText Size/Weight` or `--fontSizeBase*`/`--fontSizeHero*` tokens. *Fix:* map each typography role to the `FluentText` parameter or Fluent 2 token that produces it.

### Semantics

- **[high]** The Admin dashboard's "Projection freshness indicator" has no data source in the Admin transport (`EXPERIENCE.md:105`, `118`, `126-129`, `138`; `DESIGN.md:140-147`, `229`). `QueryResponseProvenance` and `ProjectionLifecycleState` exist only on gateway query responses (`src/Hexalith.EventStore.Contracts/Queries/QueryResponseProvenance.cs:23-29`, `ProjectionLifecycleState.cs`, consumed by `src/Hexalith.EventStore.Client/Gateway/EventStoreGatewayClient.cs`). Nothing in `Admin.Abstractions`, `Admin.Server`, or `Admin.UI` references either type (grep: zero files). The Projections page renders `ProjectionStatusType` = `Running/Paused/Error/Rebuilding` (`src/Hexalith.EventStore.Admin.Abstractions/Models/Projections/ProjectionStatusType.cs:6-16`; `Pages/Projections.razor:201-230`), which is an operator runtime status, not lifecycle evidence. Story 7.19's AC assumes provenance arrives (`epics.md:5859`), but the spine never says which Admin DTO carries it, so a dev cannot render `Current/Stale/.../LocalOnly` on the Projections or Commands tabs without first changing the `Admin.Abstractions` public contract (Story 7.5's typed client). *Fix:* add a sentence to the freshness-indicator row: "On Admin tabs this indicator is rendered only where the Story 7.5 typed Admin client exposes `QueryResponseProvenance` + `ProjectionLifecycleState` on the DTO; until then Admin projection rows show `ProjectionStatusType` and the freshness indicator renders `Unknown`." Keep the two vocabularies visibly distinct.
- **[medium]** Command investigation identifier is underspecified against the code (`EXPERIENCE.md:255`: "searches by support-provided message/correlation id"; `Flow 3`). The gateway command-status resource is keyed by `messageId` (`src/Hexalith.EventStore/Controllers/CommandStatusController.cs:23`, `CommandsController.cs:128`), while the Admin Commands page has no free-text id search — only status/tenant/type filters (`Pages/Commands.razor:52-72`) — and its rows carry `CorrelationId` (`Commands.razor:101`, `CommandSummary.cs`). AD-17 (`architecture.md:255-267`) is absent from the spine's Source Traceability table (`EXPERIENCE.md:58-69`). *Fix:* state that `MessageId` is the primary lookup key (matching the status resource), `CorrelationId` is the trace key, and add an AD-17 row saying the UI never constructs a status URL itself — it consumes the typed client's status lookup.
- **[medium]** Lifecycle colour mapping conflicts with the shipped Tenants implementation (Story 2.6, done). DESIGN.md maps stale→warning, rebuilding→neutral, local-only→neutral, unavailable→danger (`DESIGN.md:141-147`); Tenants renders Stale→`Severe`, Rebuilding→`Informative`, LocalOnly→`Important`, Unavailable→`Severe` (`ProjectionLifecycleBadge.razor:28-33`). Two Hexalith modules will colour the same state differently, and the spine claims to own the Tenants UI flow (`EXPERIENCE.md:35`, Flow 6). *Fix:* either adopt the Tenants mapping as the platform standard or record the divergence as an accepted per-module exception.
- **[low]** FR36 is cited as the authority for provenance/lifecycle (`EXPERIENCE.md:67`, `DESIGN.md:229`); the post-correction readiness report already flags FR4 as the primary authority and FR36 as consumer-parity proof (`implementation-readiness-report-2026-08-01-post-correction.md:210`). *Fix:* relabel to "FR4 / AD-15 / AD-19 / AD-20 (FR36 parity proof)".
