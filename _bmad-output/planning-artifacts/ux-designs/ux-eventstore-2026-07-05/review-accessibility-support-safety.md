# Accessibility & Support-Safety Review — eventstore

Reviewed: 2026-09-08 (fresh pass; supersedes the 2026-07-05 review whose four findings were rolled in on 2026-08-01).
Scope: `DESIGN.md`, `EXPERIENCE.md`, `index.md`, `../../ux.md`, `mockups/dashboard-overview.html`, `mockups/command-investigation.html`, `references/Hexalith.AI.Tools/hexalith-ux-instructions.md`, `prd.md` NFR/UI-governance sections. Brownfield `src/Hexalith.EventStore.Admin.UI` was consulted only to check whether a spine silence is already being filled by legacy code in a way the spine would not permit.

## Preamble

The spines are strong exactly where the memlog says the stakes are: accepted is never success, `LocalOnly`/`Unknown` never masquerade as confirmed, denied never confirms existence, deferred work is hidden/disabled/`501`, raw internals are banned from every surface, and the four 2026-07-05 findings (localization evidence, mobile mutation policy, denied-state focus/copy, live-region priority) are now answered in `EXPERIENCE.md`. What would bite a real operator is the layer *around* those rules: the spines never say who the audited actor is or show it before a confirm, never bound the "evidence pending" wait or forbid resubmitting a late-but-not-failed mutation, never map server outcomes (401/403/404/501/network) to distinct operator-visible states, and never regulate the two channels that most easily fake success or flood assistive tech: toasts and auto-refresh. Localization is answered at the string level but is silent on timestamps, time zones, plurals, invariant lifecycle codes, and text expansion. The two HTML mocks are honest about state semantics but contradict the spines on keyboard operability, legacy Fluent v4 tokens, and a decorative success-coloured banner; anyone copying their markup ships an inaccessible tab strip.

## Findings

### WCAG floor

- **high** Live-region priority is classified but placement, scoping, and throttling are not (`EXPERIENCE.md:172-180`, `EXPERIENCE.md:151`). With polling plus SignalR nudges, every "polite" stale/current flip on every stat card and every lifecycle step of every in-flight command (Overview mock shows 7 in flight, `dashboard-overview.html:298`) becomes an announcement; a screen-reader operator in an incident gets a continuous stream. Nothing says a grid re-render must not re-announce rows. *Fix:* one status region per dashboard view; announce only (a) transitions of the operation the user initiated and (b) terminal states; background refresh announces at most one summary per cycle ("Evidence refreshed, 3 rows changed") and only when something changed; never announce per-row lifecycle steps from a grid.
- **high** Auto-refresh has no cadence, no pause, and no state-preservation rule (`EXPERIENCE.md:151`, `EXPERIENCE.md:116`, `EXPERIENCE.md:115`). WCAG 2.2.1/2.2.2 require a way to pause or extend auto-updating content; the spine only says "polling remains fallback". Nothing says a poll must not reset grid sort/selection/scroll, collapse an accordion, close a drawer, or replace the row an operator is reading in a confirmation dialog. Legacy code already polls on a 30 s `PeriodicTimer` (`src/Hexalith.EventStore.Admin.UI/Pages/DaprPubSub.razor:408`), so implementers will carry that forward unguided. *Fix:* declare the polling interval and expose it with a pause/resume control in the dashboard header; refresh must preserve focus, selection, scroll, expanded sections, and open dialogs; a dialog's target facts are frozen at open time and a changed underlying row surfaces as a conflict (see Silences), not as a silent swap.
- **medium** Focus destinations are ambiguous for tab activation, deep links, and non-modal detail panels (`EXPERIENCE.md:162`, `EXPERIENCE.md:150`, `EXPERIENCE.md:168`, `EXPERIENCE.md:102`). "One focusable page title per selected tab" can be read as "move focus to the title on tab change", which breaks arrow-key traversal of `FluentTabs`; deep-link entry says only "select the right tab/detail"; focus return is specified for dialogs but not for `FluentDrawer` detail panels, which are not modal and so have no implicit return. *Fix:* user tab activation keeps focus on the tab; route/deep-link entry focuses the page title; opening a detail panel moves focus to the panel heading; closing it returns focus to the originating row/control; state this for drawers explicitly.
- **medium** Row-click is the only stated drill-in affordance and icon-only header actions have no naming rule (`EXPERIENCE.md:98`, `DESIGN.md:218`, `DESIGN.md:105`). A `<tr>` click handler is not keyboard-operable; "small utility actions" in a 44 px app bar are likely icon-only. WCAG 2.5.8 (24×24 minimum) is not mentioned anywhere. *Fix:* every evidence row exposes a focusable open action (or `FluentDataGrid` row activation via Enter/Space); icon-only controls carry an accessible name and a ≥24 px target; add the target-size floor to `DESIGN.md.Components`.
- **medium** Contrast target covers text only; disabled-with-reason has no discoverability rule (`DESIGN.md:178`, `DESIGN.md:32`, `EXPERIENCE.md:213-214`). No 3:1 non-text target for badge borders, focus ring on the accent app bar, or lifecycle-tracker fills. "Disabled with stale/unknown reason" is the primary safety pattern, yet disabled controls are contrast-exempt and their `title`/tooltip is not keyboard-reachable, so the *reason* — the thing that keeps the operator from escalating wrongly — can be invisible to keyboard and screen-reader users. *Fix:* add a 3:1 non-text contrast target; require the disable reason to render as adjacent enabled text (or a `FluentMessageBar`) associated via `aria-describedby`, not only as a tooltip.
- **low** Narrow reflow stops at "< 960px" and skeleton motion is unregulated (`EXPERIENCE.md:191-195`, `EXPERIENCE.md:113`, `EXPERIENCE.md:169`, `command-investigation.html:131`). No 320 px / 400 % zoom rule; scrolling tab strips must keep the active tab visible and reachable; the mock's `minmax(480px,…)` grid cannot reflow. Reduced motion is scoped to "state changes", which does not obviously cover shimmering skeletons. *Fix:* state that grids scroll inside their own container or stack at ≤ 400 px, tabs overflow to a menu, and skeleton shimmer honours `prefers-reduced-motion`.

### Localization

- **high** No rule for date, time, time-zone, duration, or number rendering (`EXPERIENCE.md:182-187`, `DESIGN.md:186`, `dashboard-overview.html:281`, `dashboard-overview.html:320`, `command-investigation.html:276`). Mocks show bare `08:24:12` and one `08:24 UTC`; legacy pages format with `ToString("HH:mm")` in the server culture (`src/Hexalith.EventStore.Admin.UI/Components/StreamTimelineGrid.razor:70`). Operators correlate timestamps across tools during incidents; UTC/local ambiguity is a real support hazard, and "12s" lag is a hand-built string. *Fix:* all timestamps render absolute with an explicit zone (operations default UTC, optionally the user's zone as secondary) plus a relative age; numbers/durations go through culture-aware, resource-backed formatters; add this to Localization evidence.
- **medium** Lifecycle and freshness codes are used both as enums and as visible labels with no invariant/translated split (`EXPERIENCE.md:104-105`, `command-investigation.html:272`, `command-investigation.html:296-300`). If `EventsStored`, `LocalOnly`, `Unknown` are translated, cross-language support handoff breaks (a French operator quotes a label the English on-call cannot grep); if they are not translated, the "all copy resource-backed" rule is violated. *Fix:* render a localized label plus the invariant code (monospace, never translated), and list which tokens are invariant identifiers.
- **medium** Pluralization has a prohibition but no mechanism (`EXPERIENCE.md:185`, `EXPERIENCE.md:121`, `EXPERIENCE.md:142`). Counts appear everywhere (dead letters, rows updated, retries). *Fix:* name the mechanism — per-plural-category resource keys or a shared plural formatter — and forbid `count + " items"` patterns in the conformance checklist.
- **medium** RTL, text expansion, and truncation are silent (`EXPERIENCE.md:194`, `DESIGN.md:200`, `dashboard-overview.html:318`). Nine tabs already scroll at 960–1279 px; a 30 % expansion (FR/DE) pushes "Storage & Snapshots"/"Deferred & Backlog" and lifecycle step names into truncation with no rule for exposing the full text. The mock truncates aggregate ids to `01JZ4...` with no accessible full value. *Fix:* state the RTL stance (Fluent `dir` mirroring, identifiers stay LTR), a 30 % expansion tolerance for tabs/badges/tracker steps, and a truncation rule: full value always available via accessible name or a copy action.
- **medium** Server error text passthrough is not governed (`EXPERIENCE.md:125`, `EXPERIENCE.md:239`, `EXPERIENCE.md:114`). "Safe error classification" is named but never defined, and nothing forbids rendering a ProblemDetails `detail` verbatim — which is English-only and the most common leak path for exception text. *Fix:* UI renders only resource-backed strings keyed by a server error code; server `detail` is never rendered outside an allowlisted, support-safe set; publish the classification vocabulary.
- **low** Brownfield literal strings have no migration gate (`EXPERIENCE.md:184`, `hexalith-ux-instructions.md:72-74`). `AdminResources.resx` exists but has zero references; legacy pages hard-code "Cancel", "Retry", "Back". The UX policy requires an allowlisted migration backlog for token debt; the spine has no equivalent for string debt, so a tab can be declared conformant while its legacy page remains literal. *Fix:* add a per-tab localization conformance checklist or an allowlisted literal-string backlog mirroring the token rule.

### Support-safe & fail-closed

- **critical** Nothing prevents acting on the wrong tenant from a cross-tenant view, and irreversible actions need no second acknowledgement (`EXPERIENCE.md:101`, `EXPERIENCE.md:154`, `EXPERIENCE.md:94`, `EXPERIENCE.md:97`, `dashboard-overview.html:305`, `command-investigation.html:260`). Both mocks default to "All Tenants"; the dialog "requires exact target identity" but there is no rule that the tenant is the first thing displayed, that it must match or override the header scope visibly, that bulk selection across tenants is forbidden, or that irreversible actions (archive dead letter, role change, snapshot delete, projection reset/replay) need explicit re-confirmation. Under incident pressure, three visually identical dialogs in a row is how a Wingtip message gets archived while looking at Contoso. *Fix:* the operation dialog leads with tenant/domain/target in a fixed, labelled block; when header scope is "All tenants" the dialog states so; irreversible actions require an explicit acknowledgement (checkbox or typed target id) and use the danger appearance; multi-select never spans tenants.
- **high** The acting principal is never shown before a confirm (`EXPERIENCE.md:205`, `DESIGN.md:218`, `EXPERIENCE.md:101`, `command-investigation.html:313`, `.memlog.md:20`). "Mutations must be attributable" but the header shows tenant/environment/connection, not who is signed in; only the *mock* says the audit record carries "user id". With Admin interactive OIDC deferred, the identity present in the Admin host is exactly the thing an operator cannot verify. *Fix:* header shows the current principal (display name + role set); the operation dialog's "permission context" restates "Acting as <name> with role <role>"; the post-evidence audit reference echoes that principal.
- **high** Server outcomes are not mapped to distinct operator-visible states (`EXPERIENCE.md:119`, `EXPERIENCE.md:122`, `EXPERIENCE.md:211-212`, `EXPERIENCE.md:114`). The visibility policy prefers `404` for not-implemented, denied must "not imply the resource exists", and deferred is `501` — so a `404` reaching the UI is deferred, denied, or missing, and the operator cannot tell whether to request access, file backlog, or escalate an outage. `401`/session expiry mid-dialog is not mentioned at all. *Fix:* add a mapping table: 401 → re-authenticate (preserve dialog input, no auto-retry); 403 → denied (accessible label, no existence disclosure); 404 → not found with neutral copy; 501 → "Unavailable in this release"; 5xx/network → unavailable with retry; each with its own icon + text + test id.
- **high** "Evidence pending" is unbounded and resubmission is not fenced (`EXPERIENCE.md:104`, `EXPERIENCE.md:117`, `EXPERIENCE.md:136`, `EXPERIENCE.md:284`, `EXPERIENCE.md:260`). `TimedOut` exists as a tracker state, Flow 5 says "stays evidence-pending or stale with a retry/refresh option", but no timeout is defined and "retry" after a late-not-failed acceptance duplicates the mutation. Flow 3 gets this right for command investigation; the generic dialog pattern does not. *Fix:* define the evidence-pending budget; after it, render "Outcome unknown — do not resubmit; track by correlation id" and offer only refresh/navigate; enable resubmit solely when command status is terminal non-success (`Rejected`, `PublishFailed`, `TimedOut` with confirmed non-persistence).
- **high** Confirmation lists target and effect but not reversibility, blast radius, or audit reason (`EXPERIENCE.md:101`, `EXPERIENCE.md:142`, `EXPERIENCE.md:154`, `EXPERIENCE.md:138`). Replaying a projection degrades consumers; archiving a dead letter means the message is never delivered; a role change takes effect immediately. Regulated support commonly requires a justification/ticket reference in the audit record; the spine never asks for one. *Fix:* dialog states "reversible / irreversible" and the downstream consequence in one resource-backed sentence; destructive/recovery dialogs capture an optional (or role-required) reason/ticket reference with a length bound, written to the audit record.
- **medium** URL persistence, clipboard, and export are ungoverned support-safe channels (`EXPERIENCE.md:97`, `EXPERIENCE.md:152`, `EXPERIENCE.md:201`). Filters "persist in the URL where useful" puts tenant ids and search identifiers into history and shared links; legacy code already copies correlation ids and page URLs to the clipboard with a success toast (`src/Hexalith.EventStore.Admin.UI/Layout/Breadcrumb.razor:172-180`, `Components/CorrelationTraceMap.razor:392`). *Fix:* URL state carries only tenant/domain/status/identifier filters — never cursors, ETags, or payload fragments; clipboard/export is limited to an allowlist of safe identifiers; a shared link opened without access renders the denied state from the mapping table.
- **medium** Masking is defined for payloads and tokens but not for configuration, topology, dead-letter reasons, or end-user PII (`EXPERIENCE.md:201`, `EXPERIENCE.md:46`, `EXPERIENCE.md:50`, `EXPERIENCE.md:121`, `EXPERIENCE.md:123`, `EXPERIENCE.md:45`). Topology renders DAPR component and sidecar metadata (connection strings, `secretKeyRef` names), Settings renders configuration, Recovery renders dead-letter failure reasons (often exception text), and Tenants & Access renders user identities (emails) in customer-facing contexts. *Fix:* configuration/component viewers show key names and secret *references* only, never values; dead-letter reason text goes through the same classification as errors; user identifiers display per role with no bulk listing/export by default.
- **medium** A styled deferred-operation token invites the decorative placeholder the memlog forbids, and legacy fake capability stays reachable during migration (`DESIGN.md:148-151`, `EXPERIENCE.md:106`, `EXPERIENCE.md:122`, `.memlog.md:20`, `src/Hexalith.EventStore.Admin.UI/Pages/Backups.razor:265-456`). The brownfield host today has live Create/Validate/Restore/Export backup dialogs; the spine mandates hidden/disabled but says nothing about migration order, so a partially migrated host presents both a "Deferred & Backlog" tab and a working-looking Backups page. *Fix:* the placeholder is a disabled grid row or `FluentMessageBar`, never a card; legacy deferred pages are removed or hard-disabled (`501`-backed) in the first migration story, before any new tab ships.

### Mock conformance

- **high** Tabs, filters, search, and rows are non-interactive `<div>`s (`dashboard-overview.html:282-292`, `dashboard-overview.html:303-308`, `command-investigation.html:251-257`, `command-investigation.html:258-263`, `command-investigation.html:271-285`). No `role="tablist"/"tab"`, no `aria-selected`, no focusability, `Search` is a `<div class="button">`, rows have no focusable action — contradicting `EXPERIENCE.md:149`, `EXPERIENCE.md:164`, and `hexalith-ux-instructions.md:47-52`. A reference mock whose only interactive pattern is inoperable is the single most misleading artefact for an implementer. *Fix:* add a header comment naming the Fluent component each region stands in for (`FluentTabs`, `FluentTextInput`, `FluentSelect`, `FluentButton`, `FluentDataGrid`) or replace the tab strip and toolbar with semantic `<button role="tab">`/`<input>`/`<select>` so the mock does not model raw HTML.
- **medium** A decorative success-coloured banner and a mis-toned warning (`dashboard-overview.html:43-51`, `dashboard-overview.html:269`, `command-investigation.html:175-180`). The "Support-safe dashboard" notice uses the `--success` fill for meta-commentary that is not evidence of anything — exactly the "decorative success language" `DESIGN.md:162` bans. The command-detail banner uses the warning fill with the accent (info) left border, so its severity is carried inconsistently. *Fix:* drop the notice or make it neutral; give the warning banner warning styling end to end, matching `{components.issue-banner.warning-background}`.
- **medium** Fallback CSS uses legacy Fluent v4/FAST tokens (`dashboard-overview.html:16-27`, `command-investigation.html:16-26`). `--accent-fill-rest`, `--neutral-foreground-rest`, `--neutral-layer-1` are forbidden by `DESIGN.md:180` and `hexalith-ux-instructions.md:66-68`; they do not track the V5 theme, so dark/high-contrast contrast is unverified for anything copied from here. *Fix:* reference Fluent 2 tokens (`--colorNeutralForeground1`, `--colorBrandBackground`, …) with the same system-color fallbacks.
- **medium** Two label vocabularies for one lifecycle, plus bare timestamps (`dashboard-overview.html:315`, `dashboard-overview.html:323`, `command-investigation.html:272`, `command-investigation.html:279`, `dashboard-overview.html:281`, `dashboard-overview.html:320`). Overview shows lowercase `active`/`pending`; Commands shows `EventsStored`/`Completed`; neither matches the freshness vocabulary in `EXPERIENCE.md:105`. Timestamps are zone-less except one. *Fix:* use the spine's tracker/freshness vocabulary verbatim in both mocks and render every timestamp with a zone.
- **low** Structure and small-screen gaps (`command-investigation.html:290`, `command-investigation.html:219-222`, `dashboard-overview.html:271`, `dashboard-overview.html:254-256`, `dashboard-overview.html:291`). Panel title is a `<p>` not a heading (heading navigation loses the detail panel); `<summary>` has `cursor: default` and no focus style; the hamburger is `aria-hidden` with no button and the mobile query simply hides navigation; the "Deferred & Backlog" tab is shown unconditionally although `EXPERIENCE.md:143` hides it by role. *Fix:* use `h2` for panel titles, keep native focus styling, model the nav toggle as a button, and annotate the tab as role-gated.

### Silences

- **high** Toasts and transient notifications are unregulated. Nothing in the spines mentions `FluentToast`/notification behaviour, yet the brownfield host already emits success toasts (`src/Hexalith.EventStore.Admin.UI/Layout/Breadcrumb.razor:180`). A toast reading "Command sent" is the cheapest way an implementer collapses accepted into success, and toasts disappear (WCAG 2.2.1) before a screen-reader user reaches them. *Fix:* toasts may carry only non-evidence information (link copied, filter saved); mutation outcomes render in the persistent status region and the row/dialog; toasts are dismissible, non-blocking, and never use the success variant for accepted states.
- **medium** No conflict / already-handled state (`EXPERIENCE.md:111-129`). Two operators retrying the same dead letter, or a role change against a row that changed since the dialog opened, are not in State Patterns; the nearest state is "validation failure". *Fix:* add "Conflict — target changed since you opened this action; refresh and re-evaluate" with no automatic retry, assertive priority, and focus return to the row.
- **medium** Bulk actions and command-palette "act" have no safety bound (`EXPERIENCE.md:107`, `DESIGN.md:231`). "Search/navigate/act across dashboard tabs" could bypass the operation dialog; single-character palette shortcuts collide with screen-reader keys (WCAG 2.1.4). *Fix:* palette actions always open the same operation dialog; shortcuts are modifier-based or remappable; bulk actions, if ever allowed, are per-tenant, per-tab, and confirm the exact count and identities.
- **low** Read-side audit is silent (`EXPERIENCE.md:205`). Regulated support sometimes requires evidence that a protected payload state or tenant user list was *viewed*. *Fix:* state whether protected-detail views are audited; if not, say so explicitly so stories do not assume it.
