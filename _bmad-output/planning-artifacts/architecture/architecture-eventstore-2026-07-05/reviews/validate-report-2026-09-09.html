Critical findings

C1 — Production runtime/provider authority is undefined

Finding: AD-9 makes topology one change unit and AD-25 approves oq8-postgresql-v1, but no rule selects a production actor state store, broker, deployment target, or proof boundary. PostgreSQL and Cosmos DB appear as production choices while local AppHost uses Redis; the spine records a Redis sequence-1 overwrite and forbids inferring equivalent behavior for other providers.

Why critical: Independently conforming deployments could claim readiness with different ETag, transaction, ordering, and first-write behavior; admission fencing is not a storage fence.

Disposition: Discuss, then autofix. Select one named production profile covering provider, broker, target, app IDs, overlays, secrets, resilience, and proof. The evidence-backed choice is PostgreSQL v1 under oq8-postgresql-v1; classify Redis Development-only and other providers non-authorizing until equivalent proof exists. Otherwise prohibit production traffic and name owner/trigger.

C2 — Tenant identity has no canonical source or normalization contract

Finding: AD-10 requires tenant authorization and conventions keep identity explicit, but do not define authoritative input, normalization, casing, comparison, reserved names, or omission behavior. Authorization, persistence, Admin, generated REST, and SignalR paths already disagree.

Why critical: Tenant-A, tenant-a, an omitted tenant defaulted from a first grant, and reserved values can authorize, partition admission, address state, filter reads, and form SignalR groups differently.

Disposition: Autofix. Require one explicit tenant at the first application boundary; canonicalize request values and eventstore:tenant grants in Contracts before authorization/key derivation; carry validated lowercase AggregateIdentity unchanged; never default from claims/session/config; reserve system and wildcard values; prove equivalent spellings cannot create or reveal different scopes.

High findings

H1 — Inbound sidecar-to-application credential is unnamed

AD-10 requires an application credential but does not bind carrier, issuer, receiver, claims, tenant rule, rotation, readiness, or SDK integration. Gateway, Operations, and DomainService use incompatible or absent mechanisms.

Disposition: Discuss, then autofix: choose one platform-owned receiver protocol through host SDK/ServiceDefaults; fail readiness outside Development when absent; treat caller app ID/ACLs as attribution and defense in depth unless explicitly authoritative.

H2 — Deny-by-default remains optional

AD-16 only coordinates probe exemptions for hosts that introduce fallback policy; no FallbackPolicy exists under src/, so newly mapped endpoints can be anonymous.

Disposition: Autofix: require the platform fallback policy on every HTTP host, allow only named probe/static-public paths, and scan endpoint metadata for every host kind.

H3 — Admin mutation attribution and delegation lack a durable contract

Current paths forward operator tokens, manufacture system:{appId}, accept caller actor IDs, or fall back to anonymous; audit and mutation state are separate.

Disposition: Discuss, then autofix: choose pass-through or precise delegation; derive identity only from authenticated claims; atomically (or via a resumable versioned unit) bind original actor, workload, delegation, canonical tenant, action, target, outcomes, correlation, time, and surface into append-only audit.

H4 — AD-24/AD-25 key rotation and fleet catalog can split admission authority

Per-record directory/migration phases do not define one fleet-wide active digest, reader set, secret generation, adapter registry, descriptor versions, or retention. AD-24 may revoke while AD-25 retains aliases/tombstones.

Disposition: Autofix: make a versioned deployment-overlay catalog sole authority; key adapters by (Domain, CommandType); compare digest at readiness; bind the ring as an AD-24 runtime-required OpenBao secret; require consumer acknowledgement and zero-reference retirement before revocation.

H5 — Correlation identity lacks one cross-host contract

AD-17 relies on CorrelationId, while gateway and Admin accept different formats and generate different IDs; Admin uses a parser the spine forbids.

Disposition: Autofix: put grammar/validator/generator in Contracts; mint only at first application boundary; echo and propagate unchanged; distinguish from traceparent; decide whether status identity is MessageId or CorrelationId.

H6 — Erasure has competing authorities and no ordered completion model

Read-model/checkpoint erasure, payload-key invalidation, and rebuild completion have no ordering rule or safe projection-delivery behavior for unreadable history.

Disposition: Discuss across EventStore and Parties, then update: name one orchestration authority; order cleanup/key invalidation; define typed Erased delivery/rebuild advancement; distinguish read-model, crypto, physical, and backup completion.

H7 — ProjectionVersion has provenance but no interoperable semantics

It may be opaque, monotonic, sequence, checkpoint, hash, schema version, or rebuild lineage; production has no owner/constructor.

Disposition: Discuss, then autofix: declare it opaque and add a typed checkpoint, or define one bounded platform value, producer, comparer, scope, change rule, catalog/schema binding, and rebuild/live-lineage behavior.

H8 — Poison/dead-letter semantics and Operations have no architecture owner

The existing stateful eventstore-operations workload is absent from paradigm, seed, topology, capability map, AppHost, and release identity. Defaults are consumer-specific and dead letters can be lost after retry exhaustion.

Disposition: Discuss, then update: adopt Operations with durable capture/ack/retry/replay/checkpoint outcomes, tenant identity, authorization/audit, targets, app ID, topology, and release status; or explicitly mark it non-production with fail-closed interim rules.

H9 — AD-19 mandates a result contract absent from implementation

AD-19 requires exact ProjectionDispatchResult, entry, and checkpoint types, but shipped code exposes different response/outcome types and coordinator-internal checkpoint control. Exact symbols were absent under src/ and tests/.

Disposition: Discuss, then update: mark the exact shape prospective with owner/proof gate, or re-ratify AD-19 around the shipped seam while retaining its outcome/checkpoint matrix.

H10 — Hard-coded .NET/ASP.NET security baseline is superseded

AD-11/Stack call SDK 10.0.400 and package family 10.0.11 current, while .NET 10.0.12 and SDK 10.0.401 were released 2026-09-08.

Disposition: Discuss, then update as one validated unit after restore/build/test/consumer proof. If held, label 10.0.11 a dated catalog pin with owner and revisit trigger.

H11 — Public unfenced actor mutation route contradicts AD-5/AD-25

The public request makes idempotency optional; null bypasses admission, reaches an unfenced actor method, and EnsureExecutionFenceAsync treats null as success.

Disposition: Implementation blocker plus architecture clarification: make admission/fence mandatory for every protected mutation and remove/fail the unfenced path, or scope AD-5/AD-25 to named justified operations.
