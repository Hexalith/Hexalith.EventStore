# Projection delivery guarantees

The production named-projection path is an at-least-once, order-safe delivery protocol. It expects DAPR invocation or retry workers to repeat work and prevents a repeated, stale, gapped, or conflicting delivery from silently applying a detail or index projection twice.

## Guarantee boundary

The guarantee applies to asynchronous named dispatch through `/project/v2`, the registered named handler, and its durable read-model batch. The legacy `/project` compatibility endpoint cannot reserve by projection type and does not provide this pre-handler guarantee.

Delivery identity is scoped by `(tenant, domain, aggregate, projection type)`. EventStore's persisted event `MessageId` is the duplicate identity. `SequenceNumber` is positive, gapless, and ordered only within one aggregate stream; it is never a global order. The dispatch ID and `ReadModelBatchScope.BatchId` are the highest event's persisted `MessageId` and remain unchanged on every retry.

Before calling `/project/v2`, the server conditionally writes a projection-scoped reservation with a lease and fencing token. DAPR ETag/first-write concurrency is authoritative across replicas. Only the reserved routes are invoked; detail and index routes complete independently. The handler's required durable batch must return `Completed` or `AlreadyCompleted`, and any compatibility actor/ETag write must succeed, before one conditional delivery-state transition both records completion and advances the projection checkpoint.

The outcomes are deliberately fail-closed:

- a completed exact duplicate is skipped as `delivery_already_completed`;
- an active exact duplicate is deferred as `delivery_in_progress`;
- a missing aggregate-local sequence remains retryable as `delivery_gap`;
- changed identity or canonical content fails as `delivery_identity_conflict`;
- evidence older than the retained exact-receipt window requires reconciliation;
- an older writer overwriting a v2 row is `delivery_schema_regression`;
- unavailable reads or exhausted conditional writes remain retryable as `delivery_state_unavailable`.

A timeout, cancellation, malformed response, or lost response after invocation retains the same reservation and retry identity. Repeating the same batch lets the batch protocol return `AlreadyCompleted`, after which the server can finish the delivery row without applying the read model again. A deterministic handler failure may release only the matching fence. An expired reservation is reclaimed only for handlers whose unchanged batch identity proves replay safety; the higher token fences a late completion from the expired attempt.

## Retention and reconciliation

`EventStore:ProjectionDeliveryIdempotency` has these defaults and bounds:

| Setting | Default | Valid range |
| --- | ---: | ---: |
| `CompletedReceiptLimit` | `256` | `1`-`4096` |
| `ReservationLease` | `00:05:00` | `00:00:30`-`1.00:00:00` |
| `MaxStateTransitionAttempts` | `8` | `1`-`32` |

Compaction retains the newest exact receipts by count. It also preserves the first retained sequence and cumulative completed-prefix fingerprint; state-store TTL is not a correctness boundary. A full canonical history can still prove the completed prefix before appending a new suffix. An old standalone delivery below the receipt floor cannot be proven locally and records payload-free reconciliation work instead of invoking the handler.

The authorized maintenance endpoint
`POST /api/v1/admin/projections/{tenantId}/{projectionName}/delivery-reconciliation/{domain}/{aggregateId}`
requires `GlobalAdministrator` and an attributable operator identity. It reloads the exact authoritative EventStore prefix through the already-persisted checkpoint, validates identities/order/scope, recomputes the frozen chain, and hydrates bounded receipts with operator attribution. It preserves the sequence and never invokes a projection handler or changes detail/index/batch state. A short, unreadable, wrong-scope, or fingerprint-mismatched history remains rebuild-required.

## Migration and operations

Projection delivery v2 is a maintenance cutover, not a rolling upgrade. All old servers and retry workers must be quiesced, delivery state backed up, and non-zero sequence-only rows reconciled before activating the store-global `projection-delivery-writer-protocol` marker. Readiness requires the exact v2 marker. Once activated, rolling downgrade is forbidden; projection erasure never removes the global marker.

Follow the [v2 cutover and rollback runbook](../operations/projection-delivery-v2-cutover.md). Persisted-state rehearsal evidence is recorded in [projection delivery v2 evidence](../operations/projection-delivery-v2-evidence.md).

## Optional source and completion proof

The version 1 source guard is an additive, exact-scope protocol. The [approved specification](../../_bmad-output/implementation-artifacts/spec-projection-cost-sequence-guard.md) controls its limits and acceptance. The [local qualification and acceptance record](../../_bmad-output/implementation-artifacts/evidence/story-6-4/review-5-parent-acceptance.md) records W0–W6, crash/preservation and live-sidecar observations with their actual source and runtime profiles, alongside failed or unproven checkout gates. Formal acceptance, authenticated exact-head sealed CI and the AD-12/NFR8 transition remain open. Existing environments require their own qualified maintenance cutover.

An actor-owned source-v1 chain binds the stored envelope bytes, exact scoped incarnation and admitted head. Schema2 delivery evidence binds the same source prefix to the selected owner's existing terminal batch receipt, persisted freshness and observed Idle lifecycle revision. Current inspection reads source metadata twice, the scoped row and both admission markers, lifecycle and the read-only selected-owner proof. Matching sequence alone is insufficient. A proven current observation reads no envelopes and performs no handler, model, checkpoint, notification or cleanup work. Empty work retains Unknown provenance and creates no empty receipt.

An explicitly negotiated single-event or mapped incremental tail admits the complete readable suffix before effects. The descriptor and catalog must agree on the handler semantics, and mapped append must expose its existing per-event batch receipts. Each application reread matches its admitted source and route identity before its handler. The outer dispatch ID stays the admitted head's EventStore MessageId; each changing per-event batch uses that event's original MessageId. Routes sharing a base can share an application pass while retaining their independent admission and verification passes.

Partial progress retains the original C/H, generation, dispatch and manifest while C remains unchanged. Opted-in owner batches retain their original fingerprint-bound manifest in the existing active batch marker or its private immutable manifest key. The control record stays within 16 KiB while the manifest has its separate 1 MiB ceiling. A separate authenticated recovery operation resumes those original bytes before any later handler; read-only current/receipt proof never repairs it. Completed receipts compact away the manifest reference, and the owning protocol conditionally reclaims private manifest bytes after durable output proof. Missing or conflicting identities, an unavailable original manifest and newer selected generations retain reconciliation work. A guarded batch cannot reclaim a newer live value during compaction.

New single-event owners require the explicit catalog-bound `aggregate-first-event/v1` initialization protocol. Authenticated maintenance first anchors a genuinely empty source and admits a zero delivery row without a model or completion receipt. The first admitted event's MessageId fixes the new owner generation; the aggregate ID fixes the owner identity. Empty inspection remains Unknown. Nonempty unknown scopes require reconciliation or canonical staged rebuild.

Qualified full-replay routes and cold mapped owners can use bounded canonical staged replay. They admit the complete readable 1..H prefix, bind the original head MessageId and selected owner generation, and require conditional ownership of every candidate operation before publication. The first preparation write retains the request digest and original canonical manifest bytes together; an interrupted reference save recovers those same bytes without invoking preparation again. Historical private manifest and reference formats remain readable. Mapped prefixes use the existing private part protocol. Coordinated route selections share their existing `rebuild` receipt, and delivery C advances only through the same observed-Idle finalization boundary. After delivery completion, separate conditional cleanup verifies the original selected terminal receipt and reclaims its manifest while retaining a bounded immutable reference. That reference prevents a delayed Stage from preparing again. Cleanup failure retains the original retry work and recovery material; a current probe performs no deletion. Wider explicitly configured operator rebuilds retain their established path.

Metadata advertises descriptor-bound fingerprints only when the caller requests `projectionSourceGuardVersion: 1`. An older request receives the historical route fingerprint and ordinary semantics. The two fingerprints cannot substitute for one another when authorizing owner proof. A single-event handler may explicitly advertise `canonicalReplayProtocol: "staged-full-replay/v1"` inside the descriptor. This fingerprint-bound fallback support preserves the historical disjoint single-event/full-replay metadata flags. An explicit rebuild-required result can choose one canonical fallback only after the original per-event recovery seam proves unchanged durable progress; an ambiguous response cannot switch modes.

An unchanged generic full-replay handler can opt into durable staged replay recovery through a host registration, `DomainProjectionReplayRecoveryRegistration(domain, projectionType, existingStoreName)`. The component must already own that handler's model batches. Metadata publishes a separate opaque binding attestation tied to the existing catalog identity; historical catalog and route fingerprint bytes stay unchanged. Original retry work freezes the attestation, and authenticated rebuild requests carry it in a separate header. Missing or changed bindings fail closed before preparation. Unbound routes retain their ordinary compatibility path.

This recovery lane saves the complete original conditional manifest atomically in the same owning component before staging. Fresh requests and replicas restore that exact manifest for stage, commit and verification; they do not prepare it against an advanced live model. A CAS loss reads the winner once. After checkpoint completion, cleanup verifies the original terminal batch and compacts the private manifest to a small tombstone that prevents another preparation under the same identity. Failed cleanup retains pending work. This lane uses the existing direct HTTP carrier and its actual transport limits; it does not grant tail/current authority or narrow explicitly configured wider mapped rebuilds.

Shared epoch inspection can independently verify an existing per-source terminal fold receipt and all declared writers without registration, catch-up or repair. Journal acceptance alone is unproven. This inspection does not establish complete shared-family owner selection or freshness and exceeds the selected-owner hot-path read profile once lifecycle checks are included. Shared-current qualification remains unsupported; generic batch metadata cannot replace the owning shared evidence, and a mixed catalog cannot report current from only its qualified siblings.

After source and selected-model verification, completion first records `IdleBindingPending` without advancing C. It releases only its own lifecycle token, reads the actual Idle revision, rechecks the selected receipt and revision, and conditionally completes the original fenced row. Recovery finishes the same pending work without new handler effects. Its shared thirty-second finalization and scheduler-cleanup deadline starts after the read-only frozen-history verification, so verification does not consume that independent deadline. A later source/lifecycle change reports stale even when the earlier checkpoint completion is proven. Cleanup remains separately charged work and cannot create freshness.

Guarded schema2 proof rows retain the complete message-ID digest list. The owning Dapr seam checks S(H,R) and the 4 MiB absolute proof cap before materializing the typed proof graph, rejects root and nested evidence duplicates using the configured serializer's property-name matching, and counts these additional parsing passes. The separate 4 KiB marker and 16 KiB control-row caps remain. Historical schema1 rows retain their existing configured size behavior. Selected-owner proof also rejects ambiguous owner and persisted freshness fields, including Web-deserializer case variants. Oversized or ambiguous evidence is rejected without pruning receipts or digests. These checks alone are not the complete production cost vector or workload qualification.

The actor's additive measured-range response carries the exact compact event-array byte length. The reader enforces page and pass limits from that actor-owned measurement without another envelope-sizing serialization. An oversized envelope still charges its full already-read decode and sizing bytes. Guarded readable-event admission and HTTP/replay-part transport share the fixed Web JSON profile, independently of configurable Dapr state serialization. Source metadata sizing matches the pinned actor SDK's default `Utf8JsonWriter` encoding and formatting with its configured type serializer. Inspection rejects logical metadata over 4 KiB; bootstrap checks both existing metadata and the proposed anchor before a save. This typed SDK-writer measurement does not prove provider-retained unknown fields or raw storage whitespace. Inspection also refuses a turn requiring cache/finalizer/counter recovery before any state access; the existing recovery operation must resolve that work. Compact-array measurements do not include Dapr DataContract remoting framing, which requires separate measurement.

For activated scopes, the query router separately inspects the read-only source/row/selection/Idle proof and requires the returned projection version to match the selected persisted freshness version before reporting Current. This inspection never starts tail work, pending finalization, handlers or cleanup. Empty, missing-version, unsupported shared-family and unproven evidence stays Unknown; local-only metadata stays Local-only. A regressed detail route preserves its row and effects while an independently qualified sibling may complete, and the incomplete catalog cannot report Current.

Missing or corrupt sibling admission cannot disable an activated scope's proof checks. A query for a removed or rebuild-only route checks its surviving scoped admission evidence and stays Unknown when guarded. An older unreserved retry wake-up can settle after a newer completed head only when its exact MessageId digest at its original sequence belongs to the valid scoped completed prefix and the current source, catalog, selected owner and Idle binding agree. Settlement claims that original work's own durable revision and lease; sequence comparison alone never permits deletion. Work that fails admission or cleanup remains pending with bounded backoff; its Attempt value saturates while later activations continue. A stale sampled retry revision cannot defer work already updated by a tail attempt.

An unguarded ordinary sibling uses the upgraded writer's existing named-delivery admission with a complete bounded readable prefix and the unchanged catalog fingerprint. It cannot write a guarded sibling's row or turn an incomplete catalog into Current. Its work remains independently pending until its own durable completion.

Read-only owner and per-event receipt proof validates the installed descriptor inventory against the requested fingerprint on every replica. Serving metadata in that process is not a prerequisite. An authenticated same-checkpoint reconciliation after an ordinary staged operator rebuild may bind the newly selected rebuild receipt and actual later Idle revision, while preserving the source anchor, delivery sequence, receipts, identity digests and reservation fences.

Source erasure retains its original catalog route inventory before acquiring lifecycle fences. It defers an active or pending guarded delivery, marks aggregate metadata atomically with erasure progress before deleting events, and resumes the original routes after a restart even if they have left the catalog. Inspection, bootstrap and append cannot reuse an erasing source anchor. Source cleanup releases only its own lifecycle operations; projection-model target erasure retains its separate manifest and operation.

The existing `Hexalith.EventStore` meter exports `eventstore.projection.delivery.cost` using only a closed operation-category tag. Actor invocations, internal key reads, source response/serialization/deserialization and sizing bytes, lookahead, source/route hashes, proof bytes/visits, raw model/control operations and scheduler occupancy are separate measurements. Transactions count as one RPC plus their key-mutation attempts. Prepared manifest operations are reported separately from committed logical model mutations; private candidate and compensation operations remain charged at the raw store seam. The selected mode and numeric head/checkpoint/lag are emitted through the existing delivery diagnostics. These measurements include failed attempts. The [local qualification and acceptance record](../../_bmad-output/implementation-artifacts/evidence/story-6-4/review-5-parent-acceptance.md) binds W0–W6 and live measurements to their actual source and runtime profiles and records failed or unproven gates; whole-checkout qualification, sealed CI and production acceptance remain open.

Cold bootstrap, writer/guard activation and reconciliation have separate operation categories. Bootstrap charges metadata and erasure-progress reads, event reads and decoding, readable-wire sizing, and anchor save/readback work. Readability counters include each attempted provider call and each payload decoded before a later page failure. Wire sizing includes the attempted bytes that exceed a cap. Completed returned-wire bytes remain distinct from that rejected work. Mapped replay transport counts both streamed serialization passes and each bounded part upload; these canonical bytes do not represent native HTTP body sizes or sidecar-internal retry attempts.
