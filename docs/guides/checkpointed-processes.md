# Checkpointed processes (synthetic preview)

`Hexalith.EventStore.DomainService` publishes `AddEventStoreProcesses<TCatalog, TTranslator>` as the EventStore R7–R8 producer API. The source API is in `Hexalith.EventStore.Client.Processes`; deterministic effect data is `Hexalith.EventStore.Contracts.Processes.ProcessEffect`. The local Release package proof builds version `999.0.0-process-ci-test`; it does not publish a release or authorize production use.

## Domain adapter

Supply `IProcessSourceCatalog` and `IProcessTranslator`. The catalog returns sources in strictly increasing `ProcessSource.CatalogKey` order and uses the last returned key as continuation. It must not use numeric offsets: removal of an earlier source must not make a later one disappear from a sweep. The translator fully decodes each state-affecting envelope and returns its deterministic effects in stable ordinal order. It throws for unknown or malformed evidence. An empty effect list is an explicit decoded no-op.

Register a fresh `IProcessDelegationProvider` that issues `TrustedEffectContext` for **each** `TrustedEffectSubmission` immediately before submission. The translator supplies no credential. Delegation must retain the source envelope MessageId as CausationId; a mismatched context is unavailable delegation and cannot reach target submission. The host also provides `ITrustedEffectSubmitter`, the workload `IEventStoreGatewayClient`, `IProcessDispositionAuthorizer`, and `IProcessDispositionAuditSink`. For example:

```csharp
builder.Services.AddEventStoreDomainService();
builder.Services.AddEventStoreProcesses<MySourceCatalog, MyProcessTranslator>();
```

The process API uses the gateway's workload stream read and the target actor's trusted-effect receipt authority. `FromSequence` is an exclusive lower bound; the next request reuses the last returned sequence. The runner validates the entire page's scope, positions, metadata, and serialized envelope-byte limits before effects. It requests no more envelopes than both the source-byte and worst-case translated command-byte page budgets can hold. It then fully translates, copies command bytes, submits effects, and checkpoints one envelope at a time. Encoded command type names count toward both command-byte budgets. A validated nonempty head clears stale read-failure attempts but retains attempts for the same failed envelope. It durably marks the source Incomplete before its first target effect, invalidating any prior healthy coverage. The runner yields at an envelope checkpoint when its monotonic source service quantum is spent. The source lease is renewed after delegation, before target submission, and after a terminal receipt before checkpoint CAS. The checkpoint advances only after all target outcomes for that envelope are terminal. Success, rejection, and no-op receipts are terminal. Ambiguous submission results retry with the same `EffectIdentityCodec` identity; a conflicting or mismatched receipt quarantines the source. Gateway `missing-event`, `corrupt-event`, and malformed JSON evidence quarantine with unknown failure position. Translator and delegation timeouts retry; a null receipt quarantines.

## Recovery and operations

`ProcessCheckpointStore` persists tenant-scoped checkpoint, retry, lease, fence, and quarantine evidence with ETag compare-and-swap. Candidate pages and exact markers retain sources after an authoritative catalog removes them. Registration first writes a durable source identity to the sweep's pending-publication set; a crash after any later index write can therefore be recovered without the catalog. Admission allows at most 128 simultaneous pending publications and 32 KiB of serialized pending identities in the sweep item. The entire serialized sweep record, including observations, dispositions, transitions, and repair cursors, is limited to 256 KiB. A new source above either bound remains unaccepted at its catalog cursor and readiness stays degraded; no index write begins. Normal registration uses a repairable tail hint and an eight-page durable continuation for bounded page access. A new index page is linked only after readback confirms its write. A linked absent page has unknown historical contents: repair retains the intent and unresolved evidence while probing later pages, and never replaces the page with a guessed singleton. An unfinished marker write triggers a bounded, resumable linked-page deduplication scan. Registration remains pending until both exact candidate and tenant markers read back as durable, including after a rejected marker CAS. A tenant enters the registry only after its first candidate page is durable.

The hosted `ProcessReconciler` alternates catalog and persisted candidate work under `SourcesPerPass`, retaining keyset and candidate page positions across passes and restarts. Catalog requests are capped to the remaining pass budget, so a one-source pass requests one source even if `DiscoveryPageSize` is larger. At most one publication or disposition repair consumes a pass work unit; a one-source pass reserves every third turn for repair so scans continue while an intent is stuck. The two repair queues have independent durable keyset cursors, so a failed intent cannot repeatedly take the same turn. An already retained publication lets catalog scanning advance to later keys; failed admission keeps the unaccepted key. Repair has a deadline of sixteen operation timeouts. A source has at most one run and one observation per cycle across both indexes. A busy source counts as unresolved coverage until a later cycle observes it after its owner completes. A counted observation stays pending until its source marker is durable, so a crash between those writes cannot double count it on replay. Every coverage-affecting source update gets a distinct durable transition token before its CAS write; only an observation of that exact latest token can clear the handoff. Other replicas therefore cannot complete Healthy between the sweep write and source CAS, including after a crash. Pending observations pause at a durable cursor before the whole-record byte ceiling, leaving headroom for a bounded `sweep-record-budget` reason. Durable root and tail hints distinguish an empty registry from a missing first page. A missing linked page remains unresolved and receives four bounded forward probes even without a tail hint; a known later tail extends probing across more gaps. A readable page ending before its durable tail is also unresolved and scanned toward that tail. Duplicate page identities, invalid tenant names, and offsets beyond a page are unresolved scan evidence. The sweep lease renews during a long bounded source run. A renewal fault during cleanup preserves an already completed source result; subsequent coverage writes still verify sweep ownership. A registry read refused by worker admission retains its exact page and entry cursor and yields the pass. A durable per-cycle marker counts the scan admission condition once, including when its category folds into `other`; the scan cannot complete until the page is read. Each external operation has a deadline; a timeout leaves durable degraded evidence. A completed coverage cycle is required before readiness can be healthy. Publication, direct source failure, and disposition invalidate completed coverage before the new state becomes visible.

`eventstore-processes-unresolved` is a `ready` health check. It reads the durable sweep and returns Degraded for an unfinished, unresolved, pending-publication, pending-disposition, over-capacity, disabled, stopped-host, or overdue cycle. A failed hosted pass degrades the local replica immediately, including failures before sweep acquisition; the next successful pass clears this local reason. Its data includes only counts and bounded reason categories, including `pendingObservations`, `reconciler-stopped`, and `reconciliation-disabled`. If the sweep cannot be read, readiness exposes `stateAvailable: false` and only locally known stopped, disabled, or hosted-failure categories, without asserting unknown durable counts. Startup option errors identify each failed property or capacity relationship. Registered hosts validate the disposition authorizer and audit sink at startup. Production alert routing and admission policy belong to Platform.

`ProcessDispositionService.RevalidateAsync` requires an authenticated principal, domain authorization, an existing fully published candidate, and successful durable audit. An exact durable candidate marker plus absence of a pending publication proves membership in bounded time. Recovery repairs an unfinished marker-write publication by searching linked pages before an operator can dispose it. Each audited attempt writes a new pending sweep generation **before** changing source state. An older attempt cannot mark a newer pending generation applied. A crash between those writes leaves readiness Degraded; the reconciler completes the prepared operation, then requires fresh coverage of that source. Denial or audit failure changes no source or sweep record.

Catalog, gateway, and translator **reads** may block synchronously; isolation has a finite 16-worker admission pool. Control-state reads use a separate eight-worker pool, so exhausted domain adapters can still leave durable degraded evidence. An exhausted pool rejects admission promptly with `read-worker-exhausted`; it does not queue behind uncooperative workers. Faults arriving after a caller deadline are observed. Timed-out workers keep their slots until they actually return, so in-process isolation cannot recover a permanently blocking provider. Supported adapters must honor cancellation for recovery to resume. Target submission, delegation, state writes, authorization, and audit are effectful adapters: implementations must return their task without synchronous blocking and honor the supplied cancellation token. The runtime does not abandon these writes on detached workers after a deadline. A timed-out remote target outcome remains ambiguous and is replayed with the same deterministic effect identity; it is never assumed to have failed. Authorization and audit waits have their own operation deadlines before source mutation. A completion timestamp ahead of the registered clock is invalid sweep evidence and cannot yield fresh readiness.

Tune `EventStore:Processes` through `EventStoreProcessOptions`. The configured source page defaults to 32 envelopes, but each run services at most eight and yields after its 12-second source service quantum at an envelope boundary. Serialized source envelopes are bounded by 64 KiB each and 4 MiB per page. The default maximum is four effects per envelope, with separate encoded command-byte envelope and page limits. The default operation timeout is 500 ms, and the source lease must allow at least three operation deadlines. The readiness age must be longer than that lease plus one reconciliation interval, so a dead owner does not by itself make the ready check overdue. Validation requires the source quantum to fit a complete envelope's worst-case translation, delegation, submissions, lease renewals, and checkpoint. A source page that still has more envelopes is `Incomplete` and remains in recovery. Retrying, parked, quarantined, and scan failures remain visible until validated recovery or disposition.

`SupportedCandidateCount` is the operator's supported retained population, not a deletion cap. Let N be that count, Q the source service quantum, T the per-operation timeout, B the pass work budget, I the reconciliation interval, and A the readiness maximum age. Validation requires `N × (2Q + 16T) + N × T + ceil(4N/B) × I ≤ A − I`. The `N × T` term conservatively charges one catalog request per source, which is the actual worst case for a one-source pass even when the configured discovery page is larger. The sixteen deadlines per source reserve bounded publication or disposition repair alongside scan and observation calls; the other terms cover two source visits, pass scheduling, and freshness slack. The default N is six with Q=12 seconds, T=500 ms, B=1,024, I=30 seconds, and A=5 minutes. Raise the supported count only with a verified larger freshness budget or smaller bounded service costs. New sources remain retained beyond capacity, while readiness degrades with `capacity-exceeded`. Platform owns admission and operational alert routing.

## Package proof and handoff

Run `python3 scripts/verify-process-packages.py` from the EventStore repository. The required CI job packs the whole inventory in Release and runs isolated consumers of the Contracts, Client, and DomainService packages. Its synthetic domain-service consumer starts the registered hosted reconciler and verifies a persisted checkpoint of 1 without a Works reference. The package consumer checks the public R7–R8 API shape; Story 4.15 supplies the Works translator and authoritative catalog, while Platform owns production alerts and admission.

When local Server restore blocks the required script, record that result separately and use this reproducible fallback from the EventStore repository. It builds the serialized Release Server, packs every manifest project from available restore assets, refreshes and repacks ServiceDefaults, and invokes the same isolated-consumer verifier. The required CI gate remains unchanged.

```bash
set -e
process_package_dir="$(mktemp -d)"
export PROCESS_PACKAGE_DIR="$process_package_dir"
dotnet build src/Hexalith.EventStore.Server/Hexalith.EventStore.Server.csproj \
  --configuration Release -m:1 --no-restore \
  -p:NuGetAudit=false -p:MinVerVersionOverride=1.0.0
python3 - <<'PY_PACK'
import json
import os
import pathlib
import subprocess

packages = json.loads(pathlib.Path("tools/release-packages.json").read_text())["packages"]
for package in packages:
    subprocess.run([
        "dotnet", "pack", package["project"], "--configuration", "Release",
        "--no-restore", "-m:1", "--output", os.environ["PROCESS_PACKAGE_DIR"],
        "-p:Version=999.0.0-process-ci-test", "-p:GeneratePackageOnBuild=false",
        "-p:UseHexalithProjectReferences=false", "-p:NuGetAudit=false",
    ], check=True)
PY_PACK
dotnet restore src/Hexalith.EventStore.ServiceDefaults/Hexalith.EventStore.ServiceDefaults.csproj \
  --disable-parallel -p:NuGetAudit=false -p:UseHexalithProjectReferences=false \
  -p:Version=999.0.0-process-ci-test
dotnet pack src/Hexalith.EventStore.ServiceDefaults/Hexalith.EventStore.ServiceDefaults.csproj \
  --configuration Release --no-restore -m:1 --output "$process_package_dir" \
  -p:Version=999.0.0-process-ci-test -p:GeneratePackageOnBuild=false \
  -p:UseHexalithProjectReferences=false -p:NuGetAudit=false
python3 scripts/validate-consumer-package-references.py "$process_package_dir" \
  --package Hexalith.EventStore.Contracts --package Hexalith.EventStore.Client \
  --package Hexalith.EventStore.DomainService
```
