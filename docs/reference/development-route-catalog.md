# Development route catalog composition

An explicitly enabled Development run can compose its existing gateway, domain
receivers and selected callers with `AddEventStoreDevelopmentRouteCatalog`.
Supply the actual selected resources, compiled owner declarations and adapters,
and each receiver's finite existing Dapr invocation inventory. The helper creates
canonical schema-three bytes before children start. Every participant independently
observes its installed endpoints, policies, operations, sidecar identity and actual
rendered authority component before the shared authority commits the generation.

The modeled Redis authority has an owner-profile component name, `keyPrefix=name`, no actor
role and exactly the selected participant scopes. It preserves the selected backend
and late metadata overrides. The helper locates the component through the sidecar's
actual resources path after rendering and refuses changes to the observed backend,
prefix or scopes. Mixing this authority role with an older SDK that understands only
the legacy role is unsupported; release the participating hosts together or supply
an independently isolated compatible authority backend.

The separately enabled generated human GET receiver uses actual typed generated
endpoint metadata, complete compiled owner operation schemas, the effective SDK
human authentication policy and the installed generated-route filter. It does not
change finite service dispatch or confer a service surface on human callers.
Human-only GET proxies need no authority-store scope. A selected caller that submits
commands or service requests must enroll and supply its actual observations. A
caller-only enrollment owns no executable operations and retains its real endpoint,
authentication and topology checks. The auxiliary-client role remains a separate
explicit deny-all receiver with no incoming Dapr grants or SDK receiver services.

SDK Gateway and Admin.Server hosts that retain their existing administrative MVC
calls opt in with `DevelopmentRouteCatalogReceiver.TechnicalHttp = true`. This
selects `eventstore-sdk-technical-http-composite-v1`; ordinary finite-v1 consumers
keep their prior behavior. The composite observes every marked SDK action, its
actual MVC source/delegate, loaded assembly bytes and module identity, compiled
parameter binding, JSON schemas, effective authentication policies and installed
filters. A known action that cannot qualify refuses readiness by name. GET and POST
on one path remain separate actions, including their actual framework constraints.

A nonempty technical receiver inventory requires schema 3 and activation-binding
v2. Every enrolled peer in that cohort must use a compatible SDK and binding mode.
The binding covers the complete host observations, attempt, action inventory and
receiver-owned caller/path/verb declarations. An enrolled sender intersects its
exact caller grant with the compiled action's full route and verb, uses its actual
local Dapr endpoint and refuses redirects. Peer ingress checks the full activation
binding as well as root and epoch; identical catalog roots and epochs in different
runs do not authorize one another. Absent technical membership retains the exact
legacy activation-binding v1 preimage and existing public constructors.

Technical actions supply no executable domain operations or business eligibility.
They retain their actual Human/Admin or dedicated workload policies. Both direct
authenticated HTTP and sidecar technical requests acquire a receiver-owned committed
lease before controller/model-binding effects. Human technical proxies such as
Admin.UI remain outside authority-store scopes; their actual Dapr grants and normal
authentication still apply. A supplied peer binding must be complete, and a workload
technical call cannot use the unbound human-proxy path. Catalog prepare, ready,
commit, rollback and reconcile keep their dedicated workload controls. The actual
Development Admin.UI and Sample.BlazorUI JWT issuers add one `ui` surface claim;
received OIDC tokens, client-credentials tokens and proxies are not relabeled.

An Admin receiver that uses the existing native owner actor-state/metadata reads
also supplies `ActorStateOwners = [gateway]` with the actual selected owner project.
The helper retains its fixed external Dapr HTTP coordinate and existing localhost
transport, verifies the actual evaluated CLI identity and allocated native listener
at resource startup, and supplies the same owner-specific private API credential to
that owner's app/sidecar and the Admin reader. It preserves an existing credential
and refuses conflicting handoffs. A new regular private receipt records only app
identity, canonical endpoint and credential presence; credentials and their hashes
never enter the catalog or host observation. Effective option, configuration,
receipt and private credential drift refuse before transport. Actor-state reads
require the actual enrolled Admin request scope; only the existing exact metadata
GET has the preactivation exception.

Actual native actor/config/health and signed pub/sub callbacks retain their own
SDK/channel provenance and guards. GET-only discovery/config/health handshakes work
before activation. Other qualified native deliveries use committed receiver leases.
Native RPC sinks enroll before the actual cancellable remote call; caught ambiguous
completion retains the durable fence. The existing asynchronous consistency scan
acquires its own bound background lease before returning 202, and releases it only
on known completion. This does not turn unrelated background services into catalog
participants.

Held v2 readbacks expose credential-free `AttemptId` and
`ActivationBindingDigest`, with complete required-host identities. The private
`activation.json` contains the canonical catalog and full binding inputs and can
support bounded, validated proof retention. Keep raw observation files private:
their rendered topology documents can contain component credentials. Local model
and socket tests do not establish ordinary package, runtime-image or hosted
acceptance. Persistent business storage requires an explicit `DevelopmentRouteCatalogCompositionOptions`
owner profile: a private custody directory, stable authority component and state key,
existing active/reader digest ring and its secret-map identity. The no-options helper
refuses; it never replaces digest keys because a routing cell is empty. Newly
provisioned material is suitable only with an independently owned fresh business
backend. Retain the existing ring for a persistent owner; rotation needs a separately
qualified transition. Keep options, custody and actual backend dependency files
outside logs, public proof archives and checkouts.

Custody holds an exclusive validated regular-file owner lock, preserves immutable
private generations and refuses key, owner, permission or link drift. Actual backend
dependencies resolve after allocation at the exact resource-start boundary, before
that child executes. A successor must match the retained physical backend and the
actual persisted predecessor's complete binding and epoch. Every host must pass the
normal prepare/ready/commit barrier. On disposal after application shutdown, only a
complete common generation, facets, profile, host set and v2 attempt/binding can
replace the retained pointer. Missing inputs or receipts preserve the prior custody
and private run for recovery. Retained readbacks do not prove remote quiescence;
actual outstanding authority leases still block the next transition.

For an optional owner selected by project path, call
`await selected.PrepareEventStoreDevelopmentOwnerAsync(timeout, cancellationToken)`
after selecting its project/sidecar configuration and before catalog composition.
Use the returned `Owner`, then dispose preparation after the application stops.
This runs the child's ordinary build and a separate evaluated-property query using
its actual Aspire project path, build configuration, build environment and working
directory. It follows the selected project's existing package/source mapping and
SDK selection; it adds no optional project reference and overrides no dependency
pin. Suppressed builds, custom launch-tool argument overrides and ambiguous target
frameworks refuse. Both processes share one finite deadline, followed only by bounded owned-process
cleanup; each output stream has an enforced eight-MiB cap. Failure retains private diagnostics at the reported path.
Successful preparation snapshots the managed output/dependency bytes privately,
rejects shared SDK byte drift, and records the evaluated output, SDK, module identity
and content hashes. Runtime host observation still independently verifies the
installed operations before activation.

The Sample's unchanged seven operations have explicit owner metadata. Its five
existing commands and Counter status query are public UI-only operations; Counter
projection remains an internal service operation. The five existing MessageId-v1
Mutation policies, target-only intent descriptors and projection query/actor methods
remain unchanged. The named Counter result preserves the existing JSON `count`
payload under both default and Web serializer settings. These Development policies
grant no hosted acceptance, new public transport or agent operation.

Signed, allowlisted owner-authority queries retain their exact in-flight proof and
outer committed lease. That proof is an additional check on the actual controller
path; public schema-three operations always retain their declared surface policy.
A valid service signature does not authorize a public UI-only operation. Existing
protected internal identity protocols and channel-only domain callbacks retain
their separately verified admissions.

Domain-service hosts may register a refusal-only callback with
`AddEventStoreDomainServiceTerminalRefusal(domain, wireCommand, callback, configureRejectionSerialization)` for an
exact, case-sensitive pair. Registration does not declare an executable operation,
handler or accepting admission stage. A callback returns
`DomainServiceTerminalRefusal.NoOpinion` or `DomainServiceTerminalRefusal.Reject`
with exactly one `IRejectionEvent`. Missing rules and no opinion continue the
existing exact catalog resolution, target/version checks and admission chain;
an undeclared command still refuses with 503.

This path requires existing transport authorization, an authenticated service
surface, a committed schema-three catalog, exact root/epoch/activation binding,
and the local host's committed V1 process domain and tenant scope. It applies only
to ordinary implicit-V1 requests. Explicit versions, source proofs or required
complete source, version-aware writers, asserted administrator flags, human
authority receipts, trusted effect origins and snapshot capture retain their
existing validation precedence.

The callback receives only detached immutable command data. Its payload and scalar
metadata are bounded together before copying by
`EventStoreProcessOptions.MaxCommandBytesPerEnvelope` (256 KiB by default, at most
1 MiB). Raw extension keys and values are copied into an ordinal immutable,
bounded snapshot and remain untrusted data, including spelling and ambiguity.
It receives no live request, state, source proof or administrator authority. Each exact rule configures an existing
`BoundedV1DomainSerializerProfile` and retains its own private bounded producer.
Its once-only capped serializer must produce a nonempty JSON object for the typed
rejection. This registration never installs or replaces ordinary domain-keyed or
unkeyed producers, so existing successful events and ordinary admission rejections
keep their original serialization even when absent from the refusal-only profile.
An existing ordinary bounded profile may coexist independently. The SDK uses the
rule's private producer and its bounded V1 response writer, without invoking the endpoint delegate,
accepting admission chain, processor, reservation, protected state read or
successful state/event writer. The catalog lease lasts through actual response
execution and drains on failure or cancellation.

Rule code is trusted module code and is not sandboxed. Its responsibility is
limited to refusing an unsupported command or returning no opinion. Existing
sanitized denial auditing is permitted; precommit mutation, protected state access,
reservations and successful work are forbidden responsibilities for this callback.
Rules are explicitly registered with finite domain/name lengths and at most 1,024
distinct exact pairs. Duplicate pairs fail registration.

Both the callback and its serializer are retained for the service provider's
lifetime and may execute concurrently. Use thread-safe singleton dependencies;
never capture scoped services, a live request, or mutable per-request state in
either delegate. Profile configuration runs once during registration and must be
complete before serving traffic. Existing sanitized denial-audit RPCs must use
the SDK's `RouteCatalogRemoteExecution` boundary: completed calls drain normally,
while demonstrated ambiguous remote completion retains the existing durable
catalog fence even if trusted rule code catches the failure.

The ordinary domain-service registration and the refusal registration bind
`EventStore:Processes:MaxCommandBytesPerEnvelope` without enabling the process
runtime. This budget default precedes explicit options callbacks and never binds
unrelated process settings. Registered refusal rules validate only this required
1..1048576-byte limit at startup; ordinary hosts without rules gain no refusal validation.
The limit covers the command payload plus UTF-8 scalar metadata, including
identifiers, wire command name and asserted user data, and all extension keys and
values. Extensions have a separate 128-entry ceiling; both limits are checked before
copying. The detached payload and ordinal extension dictionary are immutable.
Extension spelling, case ambiguity, empty/malformed data and null values are preserved
without normalization or interpretation as caller authority. Absent and empty extension
dictionaries remain distinct. Refusal invocation requires
the complete activation binding in addition to current transport authorization,
host identity and schema-three service surface. A legacy activation without that
capability skips the callback and continues unchanged catalog guards. Known
commands also retain their target, tenant, version, admission and step-up checks;
a known V2 selection cannot borrow another command's V1 scope.

The SDK retains the existing complete activation-v1 digest privately even when
`TechnicalHttpReceivers` is empty. Its process transport replaces caller-supplied
optional process-binding headers with this proof. Only refusal eligibility checks
its exact singleton value; missing, duplicate or stale proof skips callbacks and
continues ordinary guards. This does not change the codec preimage, ordinary peer
admission, technical membership or legacy public readbacks/custody: their v2
`AttemptId` and `ActivationBindingDigest` remain null. No host should set this header.

For request-scoped dependencies, explicitly register the service and use the typed
overload. It receives only that service, detached data and cancellation:

```csharp
builder.Services.AddScoped<WidgetDenialRules>();
builder.Services.AddEventStoreDomainServiceTerminalRefusal<WidgetDenialRules>(
    "widget", "UnsupportedWidgetCommand",
    static (rules, context, cancellationToken) => rules.EvaluateAsync(context, cancellationToken),
    static profile => profile.Add<UnsupportedWidgetCommandRejected>(
        typeof(UnsupportedWidgetCommandRejected).FullName!, "json", 1024,
        static (rejection, stream, cancellationToken) =>
            JsonSerializer.SerializeAsync(stream, rejection, cancellationToken: cancellationToken)));
```

`WidgetDenialRules.EvaluateAsync` returns `Task<DomainServiceTerminalRefusal>` and
has the same trusted refusal-only responsibility, including sanitized denial auditing.
The SDK resolves the explicitly registered service from the current request scope
only after authority, local scope, binding and budget checks, within the remote-call
lease scope. A missing service fails closed; the request scope owns its disposal.
The retained delegate and serializer must still be safe for concurrent calls and
must not capture scoped services. Both overloads share exact-pair and finite limits.

For example, place the typed rejection in its own `UnsupportedWidgetCommandRejected.cs`:

```csharp
using Hexalith.EventStore.Contracts.Events;

public sealed record UnsupportedWidgetCommandRejected(string CommandType) : IRejectionEvent;
```

Register the exact unsupported wire pair and its bounded rejection serializer at
startup, alongside the ordinary SDK domain-service registration:

```csharp
using System.Text.Json;
using Hexalith.EventStore.DomainService;

builder.AddEventStoreDomainService();
builder.Services.AddEventStoreDomainServiceTerminalRefusal(
    "widget",
    "UnsupportedWidgetCommand",
    static (context, cancellationToken) =>
    {
        cancellationToken.ThrowIfCancellationRequested();
        return Task.FromResult(DomainServiceTerminalRefusal.Reject(
            new UnsupportedWidgetCommandRejected(context.CommandType)));
    },
    static profile => profile.Add<UnsupportedWidgetCommandRejected>(
        typeof(UnsupportedWidgetCommandRejected).FullName!,
        "json",
        maximumPayloadBytes: 1024,
        static (rejection, stream, cancellationToken) =>
            JsonSerializer.SerializeAsync(stream, rejection, cancellationToken: cancellationToken)));
```

This registration adds no executable catalog declaration for the unsupported
command. Missing rules and `NoOpinion` still use the ordinary result pipeline,
including its existing success and admission-rejection serializers.

For legacy `/project`, an authenticated request for a domain with no committed
local owner and no installed matching legacy receiver retains 404. A declaration
joined to this host's target or its local auxiliary inventory establishes ownership.
Known owners retain all existing projection tenant, auxiliary and output checks,
including named-only domains; installing an uncommitted receiver still refuses.

The platform routing-header owners remain SDK transports. In addition to the
ordinary `DaprServiceInvocationHandler` and the isolated catalog state client,
`RouteCatalogInvocationHandler` owns the Development Admin actor-state read
credential. It accepts only an independently configured destination sidecar,
GET metadata or the exact scalar actor-state path, and an enrolled Admin lease
for actor state. It refuses foreign destinations, service-invocation paths,
mutation verbs and injected app-routing headers, and sends the destination's
private API token through its redirect-disabled transport. Hosts must never
set either Dapr routing header themselves.

Physical replicas use unique HostIds and independently observed executable-owner
hashes, inventories, authentication policies and ready receipts. A repeated Dapr
AppId is accepted only when those logical owner facts agree; sidecar coordinates
and private channel credentials remain independent. Component scopes and owner
metadata are coalesced only after those checks, while every physical host remains
required at the activation barrier.

An ordinary child restart can resume the exact retained committed CAS generation
after recapturing its current inputs and validating the retained activation binding.
It emits a new resume receipt and preserves prior readiness records and durable
leases. Changed coordinates or ownership require a successor transition; they are
never accepted by overwriting coordination files.

Composition requires `DevelopmentRouteCatalogCompositionOptions`. Supply an absolute
private custody directory, stable authority component/state-key names, the existing
complete digest key ring and its active/map generations. The helper never generates
replacement digest material. Provision a first key only together with an actually new,
owner-isolated business backend. Default `dapr init` Redis can retain business receipts;
an absent routing cell, lifecycle record or custody directory does not prove freshness.
Restore the original private owner profile, or select an owned isolated profile before
starting. Missing custody options refuse before model resources or child processes are
created. Changing retained key bytes, key identities or authority coordinates refuses;
automatic rotation and lost-key recovery are not supplied by this helper.

The profile has exclusive ownership while its composition exists. On disposal, after
the application and children stop, complete canonical bytes, actual rendered authority
and ACL inputs, private resolved backend dependencies, activation/readiness/commit and
resume receipts are copied into immutable, hash-inventoried custody before temporary
inputs are removed. Private digest material remains in the owner profile. Files retain
owner-only permissions. Run-scoped workload issuer credentials are not exported. If a
complete committed cohort cannot be retained, disposal preserves the private run
directory and reports refusal rather than deleting the only recovery inputs.

Recomposition builds a higher generation through `VersionedRouteCatalogBuilder` using
the retained canonical predecessor bytes and root, preserving historical idempotency
entries. Fresh physical observations bind the new attempt. The backend must be the
same retained authority backend; every host independently verifies that its actual CAS
cell has the expected predecessor, prepares, becomes ready and commits. Missing hosts
or outstanding durable leases prevent serving the successor. An empty/new cell cannot
inherit continuity from copied files. Backend replacement requires a separately
qualified owner state handoff. Independent host observation is published before waiting
for that backend, preserving diagnostics when the backend or coordinator is absent.

A prepared transition keeps new dispatch fenced while prior durable leases drain.
Bootstrap waits for that specific condition under the owning application's lifetime;
it does not expire or discard a lease. Ambiguous completion requires an explicit
`IRouteCatalogQuiescenceVerifier` that proves the exact old dispatch has stopped.
There is no default verifier. A changed-coordinate successor may reconcile through
its own independently observed pending activation, only when its immutable attempt
binding, predecessor and increasing generation agree. The old committed profile and
owner trust remain verified, and each fence must belong to the old required roster
and exact root/epoch. Old identities are never rewritten to look current. Every CAS
retry repeats authority and owner-proof validation; copied receipts, caller timeout
or elapsed time cannot substitute for actual quiescence. Every new physical host
must still become ready before the successor can commit.

Retained SDK ACL declarations use the Dapr 1.18 trie rules. Literal nodes match
prefixes; scalar `/*` is selected only for the final requested segment; terminal
`/**` also covers descendants. The retained workload status `/*/*` spelling is
bound to its known compiled endpoint as a declaration, but does not authorize the
intended two-suffix request. Its reachable short form cannot execute an unenrolled
endpoint. See the [Dapr 1.18.7 matcher](https://github.com/dapr/dapr/blob/v1.18.7/pkg/config/acl_trie.go).
