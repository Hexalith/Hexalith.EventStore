# Development route catalog composition

An explicitly enabled Development run can compose its existing gateway, domain
receivers and selected callers with `AddEventStoreDevelopmentRouteCatalog`.
Supply the actual selected resources, compiled owner declarations and adapters,
and each receiver's finite existing Dapr invocation inventory. The helper creates
canonical schema-three bytes before children start. Every participant independently
observes its installed endpoints, policies, operations, sidecar identity and actual
rendered authority component before the shared authority commits the generation.

The modeled Redis authority has an owner-profile component name, `keyPrefix=name`, no actor
role and exactly the selected participant scopes. It preserves the selected backend
and late metadata overrides. The helper locates the component through the sidecar's
actual resources path after rendering and refuses changes to the observed backend,
prefix or scopes. Mixing this authority role with an older SDK that understands only
the legacy role is unsupported; release the participating hosts together or supply
an independently isolated compatible authority backend.

The separately enabled generated human GET receiver uses actual typed generated
endpoint metadata, complete compiled owner operation schemas, the effective SDK
human authentication policy and the installed generated-route filter. It does not
change finite service dispatch or confer a service surface on human callers.
Human-only GET proxies need no authority-store scope. A selected caller that submits
commands or service requests must enroll and supply its actual observations. A
caller-only enrollment owns no executable operations and retains its real endpoint,
authentication and topology checks. The auxiliary-client role remains a separate
explicit deny-all receiver with no incoming Dapr grants or SDK receiver services.

For an optional owner selected by project path, call
`await selected.PrepareEventStoreDevelopmentOwnerAsync(timeout, cancellationToken)`
after selecting its project/sidecar configuration and before catalog composition.
Use the returned `Owner`, then dispose preparation after the application stops.
This runs the child's ordinary build and a separate evaluated-property query using
its actual Aspire project path, build configuration, build environment and working
directory. It follows the selected project's existing package/source mapping and
SDK selection; it adds no optional project reference and overrides no dependency
pin. Suppressed builds, custom launch-tool argument overrides and ambiguous target
frameworks refuse. Both processes share one finite deadline; each output stream has
an enforced eight-MiB cap. Failure retains private diagnostics at the reported path.
Successful preparation snapshots the managed output/dependency bytes privately,
rejects shared SDK byte drift, and records the evaluated output, SDK, module identity
and content hashes. Runtime host observation still independently verifies the
installed operations before activation.

The Sample's unchanged seven operations have explicit owner metadata. Its five
existing commands and Counter status query are public UI-only operations; Counter
projection remains an internal service operation. The five existing MessageId-v1
Mutation policies, target-only intent descriptors and projection query/actor methods
remain unchanged. The named Counter result preserves the existing JSON `count`
payload under both default and Web serializer settings. These Development policies
grant no hosted acceptance, new public transport or agent operation.

The platform routing-header owners remain SDK transports. In addition to the
ordinary `DaprServiceInvocationHandler` and the isolated catalog state client,
`RouteCatalogInvocationHandler` owns the Development Admin actor-state read
credential. It accepts only an independently configured destination sidecar,
GET metadata or the exact scalar actor-state path, and an enrolled Admin lease
for actor state. It refuses foreign destinations, service-invocation paths,
mutation verbs and injected app-routing headers, and sends the destination's
private API token through its redirect-disabled transport. Hosts must never
set either Dapr routing header themselves.

Physical replicas use unique HostIds and independently observed executable-owner
hashes, inventories, authentication policies and ready receipts. A repeated Dapr
AppId is accepted only when those logical owner facts agree; sidecar coordinates
and private channel credentials remain independent. Component scopes and owner
metadata are coalesced only after those checks, while every physical host remains
required at the activation barrier.

An ordinary child restart can resume the exact retained committed CAS generation
after recapturing its current inputs and validating the retained activation binding.
It emits a new resume receipt and preserves prior readiness records and durable
leases. Changed coordinates or ownership require a successor transition; they are
never accepted by overwriting coordination files.

Composition requires `DevelopmentRouteCatalogCompositionOptions`. Supply an absolute
private custody directory, stable authority component/state-key names, the existing
complete digest key ring and its active/map generations. The helper never generates
replacement digest material. Provision a first key only together with an actually new,
owner-isolated business backend. Default `dapr init` Redis can retain business receipts;
an absent routing cell, lifecycle record or custody directory does not prove freshness.
Restore the original private owner profile, or select an owned isolated profile before
starting. Missing custody options refuse before model resources or child processes are
created. Changing retained key bytes, key identities or authority coordinates refuses;
automatic rotation and lost-key recovery are not supplied by this helper.

The profile has exclusive ownership while its composition exists. On disposal, after
the application and children stop, complete canonical bytes, actual rendered authority
and ACL inputs, private resolved backend dependencies, activation/readiness/commit and
resume receipts are copied into immutable, hash-inventoried custody before temporary
inputs are removed. Private digest material remains in the owner profile. Files retain
owner-only permissions. Run-scoped workload issuer credentials are not exported. If a
complete committed cohort cannot be retained, disposal preserves the private run
directory and reports refusal rather than deleting the only recovery inputs.

Recomposition builds a higher generation through `VersionedRouteCatalogBuilder` using
the retained canonical predecessor bytes and root, preserving historical idempotency
entries. Fresh physical observations bind the new attempt. The backend must be the
same retained authority backend; every host independently verifies that its actual CAS
cell has the expected predecessor, prepares, becomes ready and commits. Missing hosts
or outstanding durable leases prevent serving the successor. An empty/new cell cannot
inherit continuity from copied files. Backend replacement requires a separately
qualified owner state handoff. Independent host observation is published before waiting
for that backend, preserving diagnostics when the backend or coordinator is absent.

A prepared transition keeps new dispatch fenced while prior durable leases drain.
Bootstrap waits for that specific condition under the owning application's lifetime;
it does not expire or discard a lease. Ambiguous completion requires an explicit
`IRouteCatalogQuiescenceVerifier` that proves the exact old dispatch has stopped.
There is no default verifier. A changed-coordinate successor may reconcile through
its own independently observed pending activation, only when its immutable attempt
binding, predecessor and increasing generation agree. The old committed profile and
owner trust remain verified, and each fence must belong to the old required roster
and exact root/epoch. Old identities are never rewritten to look current. Every CAS
retry repeats authority and owner-proof validation; copied receipts, caller timeout
or elapsed time cannot substitute for actual quiescence. Every new physical host
must still become ready before the successor can commit.

Retained SDK ACL declarations use the Dapr 1.18 trie rules. Literal nodes match
prefixes; scalar `/*` is selected only for the final requested segment; terminal
`/**` also covers descendants. The retained workload status `/*/*` spelling is
bound to its known compiled endpoint as a declaration, but does not authorize the
intended two-suffix request. Its reachable short form cannot execute an unenrolled
endpoint. See the [Dapr 1.18.7 matcher](https://github.com/dapr/dapr/blob/v1.18.7/pkg/config/acl_trie.go).
